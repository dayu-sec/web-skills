# 使用 Zod 进行运行时校验

## 适用边界

- 使用 `zod` 校验网络外部 JSON、运行时配置、localStorage、跨窗口或跨应用事件、第三方数据和其他无法只靠 TypeScript 保证的输入。
- 已由当前进程构造且类型可靠的内部对象不重复解析；生成 SDK 的输出是否再校验，以接口可信度和项目契约为准。
- 表单字段优先使用项目表单方案；只有需要共享运行时 Schema 或校验表单边界外数据时才组合 `zod`。

## Schema 与契约

- 先说明契约来源，再按必需、可选、nullable、枚举和联合结构建立 Schema；不要添加无来源别名或兼容字段。
- Zod Schema 是真源时从 Schema 推导 TypeScript 类型，不再手写同形接口。
- OpenAPI、生成类型或外部文档是真源时，让 Schema 与该契约保持一致并在测试中校验，避免形成第二套独立字段定义。
- 只有契约明确允许转换时才使用 coercion、trim、default 或 transform；不要用自动转换掩盖服务端或配置错误。

## 解析与错误

- 在不可信数据进入业务层的边界解析一次，解析成功后只消费已验证结果，不在下游反复可选链或重复 Schema。
- 契约违背应进入项目通用异常或配置失败路径，不用 `catch` 加空对象、空数组或历史猜测结构继续运行。
- 用户可修正的输入可以使用非抛出式解析并映射为表单错误；系统配置、启动契约或必须成功的响应可以沿用异常传播路径。
- Zod 错误只描述校验失败，不替代请求层传输错误、服务端业务错误或 UI 提示归属。

## 验证

- 为必需、可选、nullable、非法枚举、未知字段策略和联合分支编写代表性测试。
- 验证解析前后的类型与值，确保 default、transform 和 coercion 没有改变未声明语义。
- 涉及请求时同时使用 `$dayu-sec-web-request`；涉及跨应用事件契约时同时使用 `$dayu-sec-web-micro-frontend`。
