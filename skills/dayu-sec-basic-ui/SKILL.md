# DayuSec 基础 UI

## 工作顺序

1. 读取目标仓库 `AGENTS.md`、现有设计规范、主题配置和组件入口，确认真实业务边界与当前技术栈。
2. 区分基础层与业务层：Shell、导航、页面骨架和通用控件属于基础层；领域表单、表格、图表和流程属于业务层。
3. 阅读 [基础设计语言](references/design-language.md)，建立科技蓝语义 Token、尺寸、排版、圆角、层级和交互状态。
4. 先复用语义 Token 和已有基础组件，再新增最小视觉规则；避免页面级任意值、全局选择器覆盖和重复封装。
5. 目标项目采用 shadcn/ui 与 Tailwind CSS 时同时使用 `$dayu-sec-shadcn-ui`；采用其他组件库时遵循其项目约定或对应技术 Skill。
6. 验证键盘操作、焦点可见性、折叠/展开状态、窄屏、滚动归属、浅深主题及主要加载、空和错误状态。

## 设计原则

- 以目标项目实际导航、权限、路由和业务文案为准；设计原型只提供视觉与交互依据。
- 使用 `background`、`foreground`、`primary`、`muted`、`border`、`input`、`ring`、`sidebar-*` 等语义角色，不在组件中复制主题字面量。
- 保留原生语义元素、ARIA 状态和可预测的 Tab 顺序；图标按钮必须有可访问名称。
- 限制视觉重量：弱边界、低阴影、克制的蓝色选中态和清晰层级优先于大面积渐变、厚描边或嵌套卡片。
- 本 Skill 定义视觉语言，不规定 CSS 工具、primitive、表单状态库或源码生成方式。

## 输出要求

- 说明采用的设计依据、基础层与业务层边界，以及新增或复用的语义 Token。
- 列出布局、排版、状态、响应式和可访问性变化；具体组件技术实现由对应技术 Skill 报告。
- 报告已运行的静态、单元、构建和浏览器验证；未完成的主题、响应式或视觉检查必须明确标注。
