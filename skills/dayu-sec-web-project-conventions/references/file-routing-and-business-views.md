# 文件路由与业务视图

## 团队协议

采用文件式路由的团队 Web 项目统一区分路由入口与业务视图：

```text
src/views/
├── pages/        # 只存放参与路由生成的入口文件
└── components/   # 存放业务视图及其就近依赖
```

新建项目和主动路由重构采用该协议。已有项目使用等价目录时先建立职责映射，并只在专门的迁移任务中归一。

## `pages` 路由入口层

`pages` 只承担文件路由机制直接需要的职责：

- 通过目录、入口文件、动态参数文件和嵌套路由表达 URL 结构。
- 读取并规范化 path params、search params 和 location state。
- 执行 redirect、路由级 guard、loader、meta、layout 和 error boundary。
- 将路由上下文转换为业务视图可消费的 props，以及 callback、emits 等明确交互契约。
- 静态入口直接转导或薄封装业务视图；动态入口只保留参数和导航适配。

不要在 `pages` 中放置请求、业务状态、表单、表格列、图表配置、数据文件、样式或业务工具。不要用扫描 `exclude` 长期掩盖文件放错目录；显式错误页等非扫描路由放在普通组件目录后由路由表引用。

## `components` 业务视图层

业务视图承担：

- 页面结构、交互状态、表单、表格、图表和业务操作。
- 请求、数据转换、类型、配置、静态数据和样式。
- 加载、空态、错误态和业务级权限呈现。
- 通过 props 接收路由参数，通过 callback 或 emits 表达导航意图。

普通业务视图不依赖文件路由命名和动态参数语法。导航栏、面包屑或本身以路由为职责的组件可以直接使用 Router API，但必须保持职责明确。

## 框架适配与验证

- React 入口使用 Router Hooks 读取上下文，以 props/callback 连接业务视图。
- Vue 入口使用 Router Composables 或路由 props 读取上下文，以 props/emits 连接业务视图。
- 其他框架沿用相同职责协议，只替换路由 API 和组件通信形式。
- 验证静态、动态、嵌套和未知路径，以及直接 URL、刷新和前进后退后的参数、页面状态与选中态。
- 业务视图应能在不依赖文件路由命名的情况下测试和复用；重构不得无意改变 URL、参数语义和视觉行为。
