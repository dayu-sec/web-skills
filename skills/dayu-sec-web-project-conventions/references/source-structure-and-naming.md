# 源码结构与命名

## 使用边界

目标项目 `AGENTS.md`、框架约定和同级现有结构优先。本协议用于新建项目、新建路径和明确的独立迁移任务，不推动无关存量重命名。

## 通用源码职责

Web 项目优先采用可识别的职责边界；已有项目使用等价目录时建立映射，不机械创建空目录：

```text
src/
├── types/
├── constants/
├── configs/
├── services/
├── utils/
└── views/
    ├── pages/
    └── components/
```

- `types` 保存领域模型和跨模块类型契约，不混入运行时代码。
- `constants` 保存稳定常量、字面量集合和 `as const` 对象。
- `configs` 保存需要组装或影响运行行为的配置。
- `services` 保存业务服务、外部数据访问及其明确适配边界；有生成 SDK 时先遵循 `$dayu-sec-web-request` 的消费方式。
- `utils` 只保存不依赖页面状态、尽量纯粹且可复用的工具函数。
- `views/pages` 保存文件路由入口；`views/components` 保存业务视图及其就近依赖。

职责目录先按技术职责划分，再按领域、子领域或功能细分。不要用无边界的根级聚合文件隐藏模块所有权；框架要求的路由入口和公共包的显式导出边界除外。

## 路径命名

- React 组件目录、主组件文件及其同名样式、测试等附属文件使用 PascalCase。
- 自定义 Hook 的导出函数和主文件使用 `useXxx` camelCase，Hook 分组目录使用 kebab-case；未调用 React Hook 的普通函数不得使用 `use` 前缀。
- Vue 项目的新增源码目录和文件使用小写 kebab-case，包括组件、组合式函数、脚本、样式和测试文件；代码标识继续遵循 Vue 与 TypeScript 约定。
- Service、契约、类型、常量、配置、工具及其他一般模块使用小写 kebab-case。
- `index.*`、动态路由参数、声明文件及框架、工具链或外部契约固定的名称按实际契约保留。

## 检查

- 路径名称应能表达职责或领域，不依赖调用方猜测。
- 业务流程和外部状态不得放进 `utils`。
- 类型、常量与运行时配置不得因目录方便而混在同一模块。
- 迁移不得改变公共导入、路由、构建扫描或制品结构，除非任务明确包含这些契约变更。
