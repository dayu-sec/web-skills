# 运行时、路由与制品

## 生命周期

- `bootstrap` 只做一次性、可重复调用安全的初始化；不要在其中挂载页面或依赖尚未提供的宿主 DOM。
- `mount` 接收明确的容器和运行时上下文，在目标容器内创建应用根节点；重复挂载要么安全拒绝，要么先清理旧实例。
- `unmount` 释放 React 根、事件监听、订阅、计时器、Portal、受控 stylesheet、缓存句柄和运行时引用。
- 生命周期适配器只桥接框架与应用入口，不承载业务查询、权限推断或页面状态。
- 框架支持更新阶段时，明确哪些上下文可以热更新，以及更新失败是否需要重新挂载。

## 独立运行与集成运行

- 子应用的独立开发入口和微前端挂载入口复用同一应用装配函数，差异只留在容器、Router basename 和平台上下文适配。
- 不复制两套 Provider、主题入口或路由树，避免独立模式和集成模式行为分叉。
- 独立模式可以提供明确的开发默认值，但不能伪造生产身份、权限、应用列表或退出行为。

## 路由协同

- 明确宿主负责的顶层路径、子应用负责的局部路径以及双方使用的 history 模式。
- 构建 `base`、资源公共路径、Router `basename` 和装配路径来自兼容的单一来源；不要在多个入口手写不同前缀。
- 子应用内部导航不得越过自身边界；跨应用导航使用宿主公开能力或标准 URL 契约。
- 菜单选中、面包屑和刷新恢复必须根据当前 URL 与已声明路由推导，不依赖仅存在于内存的点击状态。
- 验证菜单进入、直接 URL、刷新、前进后退、动态参数和未知路径。

## 资源与制品

- 区分开发服务器地址、运行时入口、静态资源基址和最终部署制品路径。
- 动态导入、字体、图片、语言资源和运行时配置必须在非根路径部署下仍能解析。
- 每个子应用的输出目录和入口名称要稳定且可由装配配置引用，不覆盖宿主或其他子应用制品。
- 构建时注入到客户端的变量视为公开信息；服务端密钥和真实认证值不得进入前端制品。

## 加载与错误边界

- 宿主只处理注册、资源加载、生命周期和装配失败；子应用内部请求或渲染错误由子应用自己的边界处理。
- 局部子应用失败不应破坏宿主导航和其他已挂载区域。
- 错误状态提供可恢复动作，例如重试加载、返回安全入口或展示明确不可用原因；不要无限重试。
- 记录错误阶段、应用标识和可公开的制品信息，不记录 Token、用户数据或完整敏感载荷。
