# UI、主题隔离与验证

## UI 所有权

- 宿主拥有平台品牌区、顶层导航、全局面包屑策略、平台操作区和子应用挂载边界。
- 子应用拥有业务页面、表单、列表、详情、局部导航、请求状态和业务反馈。
- 子应用不重复宿主已经提供的页头、侧栏或全局面包屑；宿主不承载子应用业务页面。
- shadcn/ui、Tailwind CSS 和组件原语使用 `$dayu-sec-ui-shadcn`；其他组件库遵循目标项目约定。本 reference 只处理跨应用 UI 边界。

## 样式与主题隔离

- 每个应用根节点使用唯一、可定位的样式和主题作用域；选择器名称以目标仓库约定为准。
- 子应用不得覆盖 `html`、`body`、宿主布局容器、其他子应用根节点或组件库未承诺的内部结构。
- 主题模式由明确的平台契约传递；每个应用在自己的根节点装配主题 Provider、CSS 变量和组件样式作用域。
- 使用运行时创建的 stylesheet、Portal 容器或文档级主题状态时，记录所有权并在卸载时完整释放。
- CSS 变量只传递主题值，不代替运行时上下文、路由或业务状态。
- 产品视觉语言和 Token 使用目标项目已确认的规范或对应产品 UI/UX Skill；本 Skill 不复制颜色、间距和组件样式规则。

## 高度与滚动

- 宿主定义视口高度和平台壳层，挂载边界通过 Flex/Grid 把剩余空间传给子应用。
- 高度链路中的可收缩容器设置正确的 `min-height: 0`；滚动只归属于明确内容区。
- 子应用不要用固定 `100vh` 忽略宿主 Header、面包屑或内容 padding，也不要让 `body` 与内部表格同时滚动。
- 微前端运行时生成的包装节点先按框架所有权判断是否必要；不要仅为减少 DOM 层级破坏生命周期或隔离边界。

## 浮层与全局副作用

- Modal、Drawer、Popover、Tooltip 和 Notification 的容器策略必须明确，避免挂到错误 document 区域或越过应用主题作用域。
- 子应用卸载时关闭或销毁其创建的浮层、通知、临时节点、事件监听和订阅。
- 多个应用同时存在时，z-index、焦点管理和键盘操作不能互相污染。

## 验证矩阵

至少覆盖：

- 子应用独立启动、首次挂载、重复挂载和卸载后重新挂载。
- 宿主菜单进入、直接 URL、刷新、前进后退和动态路由。
- 资源加载失败、生命周期失败、子应用渲染错误和恢复动作。
- Light/Dark、主题切换、语言切换和卸载后无残留样式或监听。
- 窄视口、长文本、侧栏变化、内容滚动和浮层遮挡。
- 非根路径部署下的脚本、样式、字体、图片、语言资源和运行时配置。
- 多子应用顺序切换或并存时无样式、状态、事件和 Portal 泄漏。
