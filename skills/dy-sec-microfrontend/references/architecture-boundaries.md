# 架构与所有权边界

## 角色划分

先从目标仓库确认实际角色，不假设所有微前端都具有相同目录或配置格式。

| 角色 | 主要职责 | 不应承担 |
| --- | --- | --- |
| 宿主 | 平台壳层、顶层导航、应用装配、共享上下文入口、装配级加载与错误边界 | 子应用业务表单、业务列表、业务接口和局部状态 |
| 子应用 | 业务页面、子路由、业务请求、局部状态和卸载清理 | 修改宿主 DOM、越过自身路由边界或控制其他子应用 |
| 共享包 | 稳定类型、主题、无应用所有权的组件或工具 | 保存运行时可变业务状态、隐式访问宿主实例 |
| 装配配置 | 应用标识、入口、路径前缀、版本或其他已声明装配输入 | 承载页面实现或未声明的业务兜底 |
| 微前端运行时 | 注册、加载、生命周期调度、隔离和运行时错误传递 | 推断业务权限、页面状态或领域规则 |

一个修改跨越多个角色时，先说明为什么单一角色无法完成，再定义每个角色的最小变更和契约。不要为方便调用把业务实现提升到宿主或共享包。

## 依赖边界

- 先读取工作区依赖图、打包配置和运行时共享策略，再决定依赖由宿主提供、子应用自带或共享包导出。
- React 等有实例一致性要求的运行时依赖，只在框架契约明确时共享；不能同时依赖隐式全局和本地副本。
- 共享包只导出稳定公共入口，不让应用读取包内部文件或依赖另一个应用的源码相对路径。
- 版本不兼容应在安装、构建或装配阶段暴露，不用运行时字段猜测掩盖。

## 跨应用通信

- 优先使用显式类型化契约：props、运行时上下文、事件载荷、共享服务接口或标准 URL。
- 定义发送方、接收方、事件名称、载荷类型、时序、幂等性和取消订阅责任。
- 主题、语言、身份摘要等平台上下文与业务状态分开；不要把业务实体或表单草稿放进全局事件总线。
- 禁止通过 DOM 查询、可变全局对象或直接导入另一个应用内部模块完成通信。
- 修改通信契约时，同时检查旧消费者、重复订阅、卸载后回调和错误传播。

## 配置与安全

- 运行时装配配置只保存部署后需要变化的输入；稳定常量留在代码内，敏感值不进入客户端配置。
- 路由前缀、入口地址和制品版本必须有单一真源，生成副本要能追溯来源。
- 不在全局 Skill、示例配置或提交文件中保存真实域名、内网地址、账号、Token、客户信息或项目快照。
