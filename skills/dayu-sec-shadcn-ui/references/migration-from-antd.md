# 存量组件库迁移

本 reference 以 Ant Design 迁移为常见示例；迁移其他组件库时使用同样的所有权、Provider、样式和验证方法。

## 划定边界

- 先盘点组件 import、Provider、Locale、主题、图标、Portal、全局样式、类型和二次封装，确定最后一个真实消费者。
- 新基础层使用项目自有 shadcn/ui 源码；存量库只服务尚未迁移的明确区域。不要为了基础层迁移顺带重写路由、权限、请求或业务状态。
- 需要阶段性共存时，在最小边界保留旧 Provider 与主题桥接；新 Shell 和新组件不继续依赖旧组件库 DOM。

## 迁移顺序

1. 建立入口 CSS、语义 Token、`cn()` 和必要基础组件。
2. 替换 Shell、导航、顶栏与加载、空、错误等通用反馈，保留原有输入契约。
3. 替换页面骨架、按钮、输入、卡片和轻量浮层。
4. 最后迁移领域表单、表格、树、复杂选择器与依赖二次封装的组件。

每次只处理一个可验证边界，并同步删除该边界不再使用的 import、局部覆盖和适配层。删除 Ant Design 的 `ConfigProvider`、Locale、主题和依赖前，必须证明最后一个消费者已经消失。

## 共存与样式

- 从同一组语义 Token 派生两套组件的主色、背景、文字、边界、圆角和控件高度，桥接只保证视觉连续性。
- 禁止用全局 `.ant-*` 选择器强行模拟新组件外观；旧组件优先使用其 Token 或页面局部作用域修复。
- Tailwind Preflight 发生冲突时先证明真实选择器与加载顺序，再做局部修复，不以关闭全部基础样式掩盖问题。
- 两套 Portal 的容器、z-index、滚动锁、Escape 和焦点回收必须分别验证。

## 完成条件

- 源码、样式、Provider、Locale、主题和类型中无旧组件库引用，锁文件不再解析相应运行时包。
- 类型、Lint、测试与生产构建通过，旧库不再进入产物 chunk。
- 真实浏览器覆盖关键路由、键盘、浮层、深浅主题、窄屏和历史导航；如果仍有共存区域，交付时逐项列明。
