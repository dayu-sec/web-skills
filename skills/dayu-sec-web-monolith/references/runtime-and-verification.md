# 运行与验证

## 入口发现

按职责定位实际文件，不假设固定名称：

| 职责 | 优先检查 |
| --- | --- |
| 工程与命令 | `package.json`、锁文件、工具版本和构建配置 |
| 应用渲染 | `main`、`bootstrap`、`app` 或根组件入口 |
| 路由 | Router 创建、文件路由生成、basename/base 和错误边界 |
| Shell | Layout、Header、Aside、Content、Breadcrumb 和页面出口 |
| 应用基础设施 | 请求、主题、语言、Query、权限、日志和配置入口 |
| 本地运行 | dev server、proxy、环境变量和 SPA fallback |

先确认入口之间的真实调用链，再修改其中一层。不要从文件名猜测所有权，也不要用构建成功代替路由和可见行为验证。

## 验证矩阵

- 运行项目已有的类型、Lint、格式和测试命令。
- 修改构建、路由、入口、Provider 或 Shell 时运行生产构建，并检查输出目录和资源基址。
- 验证静态、动态、嵌套和未知路径的直接 URL、刷新、前进后退和选中态。
- 使用项目真实预览或等价静态服务器验证 SPA fallback，不只验证开发服务器。
- 修改布局或全局 Provider 时检查页面内容是否被无故重建，以及主题、语言、请求和错误边界是否仍覆盖全部路由。
- 修改可见 UI 时按实际影响补充窄视口、滚动、键盘和 Light/Dark 验证。

最终报告区分配置/源码静态审计、质量命令、生产构建和真实 HTTP/浏览器运行；未执行的层级必须明确说明。
