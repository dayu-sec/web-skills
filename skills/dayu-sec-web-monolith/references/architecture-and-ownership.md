# 架构与所有权

## 单体应用边界

单体 Web 应用在一个部署和运行单元内组合应用入口、Router、Provider、Shell、业务视图和应用内部基础设施。代码可以按领域或功能模块拆分，但不为这些内部模块引入微前端生命周期或跨应用通信。

| 单元 | 主要职责 | 不应承担 |
| --- | --- | --- |
| 应用入口 | 创建应用根、初始化必要基础设施并装配根 Provider | 业务页面和具体业务流程 |
| Router | URL、参数、导航、路由级 guard、layout 和 error boundary | 业务请求、表单和页面局部状态 |
| Shell/布局 | 稳定应用框架、全局区域、导航和页面出口 | 具体业务页面、业务服务和表单 |
| 根 Provider | 主题、语言、请求、查询和应用级上下文装配 | 隐式保存无所有权的业务状态 |
| 业务视图 | 页面结构、交互、数据、局部状态和业务操作 | 控制全局 Shell 或伪造跨应用边界 |
| 应用基础设施 | 请求、主题、语言、日志、权限和配置适配 | 反向依赖具体业务视图 |

## Shell 与业务视图

- Shell 组件树和页面出口应保持稳定；布局模式切换不得无故重建业务页面。
- Header、Aside、Content 等区域由 Shell 编排，业务视图通过明确出口渲染。
- 菜单、面包屑等路由投影可以属于 Shell；业务表格、表单、图表和详情属于业务视图。
- 全局副作用由明确的应用基础设施拥有，并在入口或 Provider 边界初始化；不要散落到业务组件。

## 变更检查

- 修改入口、Provider 或 Shell 前，列出受影响的所有页面和全局副作用。
- 需要跨应用协作时，先确认是否仍是外部服务调用，还是已经改变部署和运行所有权。
- 如果任务确实拆分单体，先冻结现有路由、数据、主题和错误契约，再使用 `$dayu-sec-web-micro-frontend` 设计迁移后的边界。
