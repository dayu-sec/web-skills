# DayuSec 内部运营 UI

## 工作顺序

1. 读取目标仓库 `AGENTS.md`、产品规格、现有主题和真实页面，确认用户角色、任务频率、数据规模、权限、风险、主要输入设备和当前组件库；原型只作为证据，不覆盖已确认的项目事实。
2. 确认目标属于内部运营、工作台或管理后台；本 Skill 独立拥有此类产品的科技蓝语义、尺寸、页面模式和交互规则，不把这些结论提升为跨产品基础设计语言。
3. 设计方向、方案评审或传统后台改造时，读取 [设计原则与反模式](references/design-principles-and-anti-patterns.md)，先明确效率、准确性、可控性和稳定性目标。
4. 处理导航、工作台、仪表盘、主从详情、复杂表单、配置或审计页面时，读取 [信息架构与页面模式](references/information-architecture-and-page-patterns.md)，按任务选择模式，不按后端模块或视觉潮流套模板。
5. 处理筛选、批量操作、异步反馈、危险操作、快捷键、弹层、自动刷新或异常状态时，读取 [交互、状态与容错](references/interaction-states-and-recovery.md)。
6. 新建设计系统、调整密度，或任务涉及内外间距、文字大小、行高和控件尺寸时，读取 [科技蓝视觉与尺寸基线](references/visual-system-and-sizing.md)；先映射目标项目已有 Token，再新增缺失角色。
7. 按实际技术栈追加最小实现 Skill；不要为套用本规范替换已满足任务需求的组件库，也不要在页面中散落任意像素值。
8. 用真实文案、权限、长标识、空数据、错误、大数据量和连续操作验证任务；同时检查键盘路径、焦点、缩放、滚动归属、布局稳定性及浏览器几何。

## 决策原则

- 以用户任务而非角色数量、数据库表或后端模块组织界面；角色决定默认入口和能力边界，不复制整套导航。
- 允许专业场景具有较高信息密度，但密度必须来自清晰层级、紧凑节奏和可选密度档位，不能靠缩小正文、点击区或状态反馈换取。
- 科技蓝只承担品牌主操作、当前项和焦点等明确语义；告警、成功、警告、中性状态使用独立语义色，并同时提供文字或图标。
- 优先保留上下文、选择、滚动位置和视觉锚点；详情抽屉、模态框、Bento 网格、深色模式或动画都不是默认答案。
- 对高频路径优化点击数和等待，对高风险路径优化确认、可逆性、权限和审计；不要用同一套交互处理两者。
- 视觉完成不等于任务完成。必须验证数据可扫描、操作可发现、状态可恢复、权限不误导和大数据量下可用。

- [交互、状态与容错](references/interaction-states-and-recovery.md)：筛选、选择、批量操作、异步状态、弹层、危险操作、快捷键、自动刷新和恢复路径。
- [科技蓝视觉与尺寸基线](references/visual-system-and-sizing.md)：颜色使用边界、间距刻度、字阶、控件尺寸、密度档位和可复制 Token 骨架。

## 输出要求

- 说明目标用户、核心任务、频率、风险、数据规模及选用的页面和交互模式，区分项目事实、原型参考和本 Skill 基线。
- 列出复用或新增的语义 Token、密度档位及间距、文字、控件尺寸；说明偏离基线的业务或组件库原因。
- 指出避免或移除的传统后台反模式，并报告任务效率、状态容错、可访问性、性能和浏览器视觉验证证据。
- 未进行真实浏览器、目标权限、真实数据量或触控设备验证时，明确标注验证边界，不以静态源码或构建成功代替运行时结论。
