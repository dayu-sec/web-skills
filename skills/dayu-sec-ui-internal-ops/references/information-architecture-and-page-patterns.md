## 1. 从角色到任务工作台

### 1.1 先建立任务模型

1. 列出角色，不直接为角色创建导航。
2. 为每个角色记录高频任务、输入、关键判断、动作、完成条件和失败风险。
3. 合并共享同一任务闭环的角色，形成少量稳定工作台。
4. 把权限下沉到数据范围、字段、按钮、Tab 和操作级，不复制工作台。
5. 为角色配置默认工作台和最近上下文，保留访问其他授权工作台的稳定入口。

工作台应对应可闭环的任务场景，例如“处理队列”“调查记录”“配置并发布”“监控运行”“审批变更”，而不是对应某张表、某个服务或某个组织名称。

### 1.2 控制工作台数量

- 一个工作台内的对象、节奏和完成条件一致时合并。
- 用户需要明显切换心智、权限、数据时效或风险等级时拆分。
- 先追求稳定和可理解，不预设固定数量；若一级入口持续增长，重新检查是否按功能而非任务拆分。

## 2. 全局信息架构

### 2.1 Shell 层

Shell 只承载跨页面稳定能力：

- 产品和当前空间标识。
- 工作台级导航与当前项。
- 全局搜索或命令入口。
- 跨页面通知、任务进度和用户菜单。
- 确有需要的环境、租户或组织切换。

不要把每个页面动作、筛选器或状态统计塞进全局顶栏。全局能力与页面能力必须通过位置和所有权区分。

### 2.2 导航层级

- 一级导航表达稳定任务域，使用清晰名词或动宾短语。
- 二级导航表达工作台内稳定子任务；临时筛选、视图和对象详情不占用导航层级。
- 尽量控制在两层可见导航；更深关系使用页内 Tab、步骤、目录或对象链接。
- 折叠侧栏仍保留当前项、图标可访问名称和可发现的展开路径。

### 2.3 全局搜索与命令

- 全局搜索用于跨对象定位；结果分组展示对象类型、关键上下文和可执行动作。
- 命令面板用于高频跳转和动作，不替代可见导航，也不隐藏唯一操作路径。
- 搜索与命令需要完整键盘操作、最近记录、空结果和权限过滤；结果不得泄漏无权对象。

## 3. 页面骨架

按任务需要组合以下区域，不要求每页全部出现：

1. **定位区**：面包屑或工作台上下文，仅在层级不明显时使用。
2. **页头**：页面标题、简短状态或说明、一个主要动作。
3. **任务工具区**：搜索、常用筛选、视图切换、刷新、导出和次级动作。
4. **上下文摘要**：只展示会改变当前决策的指标、异常或范围。
5. **主工作面**：队列、主从详情、表单、画布或时间线。
6. **状态与恢复区**：加载、空、无结果、错误、过期、权限和批量进度。

页头和工具区是否固定由滚动长度和任务频率决定。固定元素必须避免遮挡内容、抢占过多垂直空间或形成多个互相竞争的滚动容器。

## 4. 页面模式选择

| 任务特征 | 首选模式 | 关键约束 | 不宜使用 |
| --- | --- | --- | --- |
| 浏览、比较、筛选大量同构记录 | 结构化列表或队列 | 呈现核心信息、当前范围和明确操作 | 卡片墙、把每项操作都做成按钮组 |
| 在队列中连续查看并处理详情 | 主从工作台 | 保留列表上下文、选中、滚动和详情锚点 | 每条记录都跳新页面或开模态框 |
| 深度调查、跨多个子对象 | 完整详情页或可调整分栏 | 可复制 URL、清晰目录、持久上下文 | 固定窄抽屉承载复杂任务 |
| 少量关键指标和趋势总览 | 仪表盘或规则网格 | 指标可行动、有基线、有下钻 | 为视觉节奏制造无关卡片 |
| 创建或编辑复杂对象 | 分区表单、步骤流或设置页 | 保存边界、校验、草稿、脏状态和发布状态 | 超长单列、弹窗套表单 |
| 修改配置并影响运行 | 编辑—校验—预览—发布 | 版本、差异、权限、回滚和审计 | 自动保存后立即生效且无提示 |
| 查看事件演进或操作记录 | 时间线或审计记录 | 时间、主体、动作、对象、结果和详情 | 仅用颜色表达事件类型 |
| 简短阻塞决策 | 模态框 | 单一任务、明确退出、焦点约束 | 多步骤复杂编辑或多层模态框 |
| 保留背景上下文的辅助详情 | 抽屉或侧面板 | 宽度随内容和视口、可关闭、焦点回收 | 把所有详情统一成固定 `vw` |

## 5. 常见功能模块

### 5.1 仪表盘与概览

- 从用户要做的判断倒推指标，不从“有哪些数据”开始排列卡片。
- 每个指标至少提供当前值和一个有意义的比较维度，例如目标、历史、阈值或变化原因。
- 异常指标连接到筛选后的对象或处理入口；不可行动的装饰数字应下沉或移除。
- 图表选择由问题决定：趋势用折线，类别比较用条形，构成用堆叠或占比；不要默认使用环图、面积渐变或 3D。
- Bento 或不等宽网格只用于确有不同信息权重的概览，不用于表单、队列和密集操作页。

### 5.2 列表与队列

- 把状态、优先级、主要标识和关键判断信息放在扫描路径前部，把低频元数据和操作放后部。
- 排序、筛选、范围和视图状态需要清晰、可复位，并在需要分享、刷新或返回时保持可恢复。
- 单项操作保留高频动作和更多菜单；危险动作不与常规动作等权并排。
- 数据量较大时，先按目标用户的定位、选择、返回、导出和可访问性需求确认加载策略。

### 5.3 筛选与视图

- 常用筛选常驻工具区，高级筛选可展开但必须显示已生效条件数量和清除入口。
- 明确区分即时筛选与“应用”式筛选；同一页面不要混用没有提示的提交模型。
- 支持保存视图时，区分个人视图、共享视图和系统默认，并显示当前视图是否有未保存修改。
- 零结果状态显示当前条件、清除或调整入口，不误用初次空数据插画。

### 5.4 主从详情

- 左侧主列表保持选中项、筛选和滚动位置；右侧详情保持标题、状态和主要动作锚点。
- URL 或可恢复状态记录当前对象，刷新和返回不应丢失工作上下文。
- 详情宽度由最重要内容决定。需要复杂对比或长流程时使用可调整分栏或完整页面。
- 对象切换时避免整个详情闪白；保留结构骨架并明确正在加载的新对象。

### 5.5 复杂表单

- 按用户心智和提交边界分组，不按接口对象嵌套层级排列字段。
- 默认使用可见标签；占位符只提供示例，不承担字段名称。
- 字段宽度反映预期内容，不为填满网格把短值输入框拉到全宽。
- 就地显示校验，提交时聚合错误并把焦点移到可操作的错误摘要或首个错误。
- 长表单提供稳定分区导航、脏状态提示、草稿或离开保护；不要用多列压缩阅读顺序。

### 5.6 配置、审批与发布

- 区分草稿、已校验、待审批、已发布、失败和已回滚等状态。
- 展示当前版本、将要影响的范围、差异、计划时间和执行者权限。
- 发布或批准前预览影响；执行后提供进度、部分失败明细、重试和审计入口。
- 自动保存只保存草稿，不静默改变线上生效状态。

### 5.7 权限与组织管理

- 同时展示主体、资源范围、能力和继承来源，避免只用大量不分组复选框。
- 对继承、覆盖、冲突和最终有效权限提供解释。
- 无权限控件的隐藏或禁用取决于是否需要让用户理解能力存在；禁用时说明原因和申请路径。
- 权限变化是高风险操作，需要影响范围、确认、审计和必要的重新认证。

### 5.8 审计与历史

- 至少包含时间、主体、动作、对象、结果和可展开详情。
- 使用绝对时间作为主要审计证据；相对时间可作为辅助。
- 支持按主体、对象、动作、结果和时间筛选，并保留导出范围说明。
- 敏感值按权限脱敏，导出与复制也遵循相同边界。

## 6. 响应式与空间降级

内部运营页面通常以桌面为主，但仍需定义较窄窗口、缩放和触控设备行为：

1. 保留标题、当前状态、主要动作和核心数据，先隐藏装饰和次要摘要。
2. 多栏布局依次降级为可调整分栏、抽屉或单栏页面，不把每列压缩到不可读。
3. 工具栏可换行或将低频动作收入明确菜单，不能只缩小控件。
4. 触控或粗指针环境提升目标尺寸和间距，不直接复用紧凑桌面模式。
5. 在浏览器缩放下检查固定页头、弹层和双滚动容器，确保焦点内容不会被遮挡。
