# 服务、错误与验证

## 职责边界

| 层级 | 负责 | 不负责 |
| --- | --- | --- |
| 请求配置 | 实例名、基础地址、超时、请求头和拦截器 | 业务字段映射、页面提示和 UI 状态 |
| 请求入口 | 初始化、获取实例、清理和稳定导出 | 复制 `get`、`post` 或业务接口方法 |
| 业务 Service | 可读的接口调用、契约类型和必要映射 | 路由、组件状态和全局副作用 |
| 生成 SDK | 使用现有请求实例或极薄适配器执行生成契约 | 复制生成方法或维护第二套请求配置 |
| Query 或状态库 | 缓存、并发、刷新和界面数据状态 | 重新实现底层请求实例、认证或错误标准化 |

业务代码直接消费稳定请求实例或业务 Service。不要新增无语义的 `getRequest()`、手写 HTTP 方法转发器，或同时维护请求库、SDK 和 Query 库三套重试与错误提示。

## TanStack Query

- React 服务端状态统一使用 `@tanstack/react-query`；Query function 调用业务 Service 或生成 SDK，不在组件或 Query 中直接拼接底层 HTTP 请求。
- Query key 使用稳定数组，并包含决定响应的资源标识、筛选、分页和租户等契约参数；不要使用不可序列化对象或遗漏关键参数。
- Query 负责缓存、并发、失效、刷新、轮询、重试和界面异步状态；请求实例继续负责基础地址、请求头、认证、传输和标准化错误。
- 写操作使用 mutation，并按业务一致性要求失效、更新或移除相关缓存；不要同时把同一远程数据复制到 Zustand 或 Context 维护第二份真源。
- URL、表单草稿、临时弹窗和纯客户端交互状态不放入 Query Cache；分别交给 Router、表单方案、React 或客户端状态库。
- 模板可以预置依赖，但没有真实 Query 时不为证明依赖而增加 Provider、示例请求或演示页面。接入时由当前应用创建和持有 QueryClient。
- 单体和每个微应用默认分别拥有自己的 QueryClient；跨应用共享缓存必须是明确的运行时契约，并同时使用 `$dy-sec-microfrontend`。
- 请求层与 Query 不重复重试、吞错或提示；说明每个策略的唯一所有者，并验证错误边界和卸载后的后台行为。

## 错误归属

- 请求失败默认继续向调用方或运行时错误边界传播，不在底层静默吞掉。
- 请求库标准化错误只描述传输和请求基础设施；业务错误字段必须有接口文档、OpenAPI、生成类型或项目已验证契约，并组合 `$dy-sec-data-contract-first`。
- 未知错误、网络错误、超时和取消进入项目通用失败路径，不拼接猜测字段伪装成业务提示。
- 关闭 loading、submitting 或临时锁定状态时优先使用 `finally`，不为状态回收额外创建 `catch`、`Promise.reject` 或第二条提示链。
- 全局错误策略只承载确有全局归属的副作用；接口级文案和局部交互留在业务边界，避免底层、Query 和组件重复提示。

## 验证矩阵

- 依赖：安装与锁文件稳定，普通依赖、peer dependency 和直接导入一致，没有底层深导入。
- 类型：根入口运行时 API、公开类型和生成声明能被真实消费者解析。
- 运行时：初始化早于业务请求，重复初始化不重复注册，实例冲突能暴露并回滚。
- 请求头：鉴权和语言值按当前状态注入，缺省值不产生伪请求头，消费方拦截器顺序不变。
- 错误：标准化错误继续传播，业务错误只解析约定结构，UI 状态通过 `finally` 回收。
- Query：key 覆盖全部响应参数，mutation 后缓存一致，重复挂载不产生重复 Provider，服务端状态没有复制到客户端 Store。
- 清理：只释放当前所有者资源，重复挂载能重新初始化，不影响相邻应用实例。
- 工程：运行目标仓库已有的 typecheck、Lint、格式、测试和构建；库同时执行示例构建、打包清单和最小消费者验证。
