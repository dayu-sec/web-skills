# Mock 目录与入口边界

## 适用边界

本协议约束 Web 项目本地 Mock 的目录、入口扫描和辅助文件组织，不定义具体响应字段、状态码或业务契约。开始前读取目标仓库的 `AGENTS.md`、包管理文件、构建配置和现有 Mock；插件行为以仓库实际安装版本和配置为准。

## 目录协议

将单个、明确服务于整个项目的 Mock 定义辅助文件保留在 Mock 根目录，将具体接口和业务场景的可扫描入口按后端服务或稳定业务域放入子目录：

```text
mock/
├── defineMock.ts
├── platform/
│   └── health.mock.ts
└── identity/
    ├── user.mock.ts
    └── permission.mock.ts
```

示例中的 `platform` 和 `identity` 是中性占位名称；实际目录必须来自目标仓库的服务边界、接口契约或既有业务域，不按页面、临时需求或 Agent 猜测命名。

- 根目录辅助文件承载项目统一的 URL 前缀、默认响应处理或配置转换，不直接声明业务接口。
- `*.mock.ts` 等插件可识别文件是 Mock 入口；`defineMock.ts`、类型、fixture 和工具文件不得使用入口后缀。
- 多个共享辅助文件出现后再建立 `shared/`、`fixtures/` 或等价目录；不要为单个文件预建空层级。
- 一级目录优先映射后端服务；没有服务划分时使用稳定业务域。不要额外套一层无信息量的 `business/` 或 `services/`。
- 一个业务域规模较小时允许一个资源文件包含少量相关配置；文件过长或同一接口存在大量分支时，再按资源、接口或稳定场景细分。
- 正常、空数据、无权限和异常等少量响应优先使用插件的 `scene`、`validator` 或同文件配置表达，不以场景名称取代服务与业务域层级。

## 扫描与依赖判断

先检查插件的 `cwd`、Mock 根目录、`include` 和 `exclude`，不要仅凭目录名判断是否支持子目录。

`vite-plugin-mock-dev-server` 的默认 Mock 根目录通常为 `mock`，入口模式为递归形式 `**/*.mock.{js,ts,cjs,mjs,json,json5}`。当目标仓库安装版本仍采用该默认值且没有覆盖 `include` 时，移动到任意层级子目录无需修改插件配置。核对入口以该版本的类型声明、官方配置文档或实际解析结果为准。

- `**/` 表示递归发现子目录；只匹配 `*.mock.*` 的模式不会把 `defineMock.ts`、fixture 或普通工具文件作为入口。
- 被入口 import 的辅助文件属于依赖，不需要伪装成 Mock 入口。移动后应验证插件是否继续跟踪依赖并支持热更新。
- 目录层级不决定请求 URL。不要因为文件移入子目录而擅自修改接口路径、前缀或响应契约。
- 若项目显式收窄 `include`，保留其格式边界；只有任务明确要求时才扩展为其他后缀。
- 使用路径别名导入根目录辅助文件时，同时核对构建工具和 TypeScript 的 alias/path 映射。入口文件移动后，根目录辅助文件的绝对别名通常不需要变化，相对 import 必须按新位置更新。

官方入口：

- [目录与文件管理](https://vite-plugin-mock-dev-server.netlify.app/guide/file-management)
- [MockServerPluginOptions](https://vite-plugin-mock-dev-server.netlify.app/api/mock-server-plugin-options)

## 迁移步骤

1. 列出当前 Mock 入口、辅助文件、fixture、相互 import 和插件扫描配置。
2. 从已有服务、接口或业务模块中确定目录名称；无法由仓库事实确认时先保留现状或请求用户决策。
3. 保留项目级根目录辅助文件，只移动具体 `*.mock.*` 入口及其就近数据。
4. 更新相对 import、测试路径和显式 include/exclude；递归默认配置已覆盖时不添加冗余配置。
5. 目录迁移不顺带改写 Mock 数据、概率规则、接口 URL 或响应契约，除非任务同时明确要求。
6. 检查版本控制差异能够识别为移动，避免漏交新目录或误删辅助文件。

## 验证

- 运行目标仓库的类型检查、Lint 和格式检查。
- 启动实际开发服务器，至少请求每个新增一级目录中的一个 Mock 接口。
- 确认响应内容、状态码和请求匹配与迁移前一致，并从插件日志或调试信息确认来源文件位于新目录。
- 修改一个入口后确认热更新生效；若本次移动了或修改了共享辅助文件，再验证依赖更新。
- 检查非入口辅助文件未被独立加载，未出现空配置、重复路由或扫描冲突。
