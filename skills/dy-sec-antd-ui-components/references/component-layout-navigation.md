# 布局与导航

## 适用任务

- 应用壳层、侧边栏、页头、面包屑、菜单、标签页、下拉菜单和布局间距。
- 页面内容区与应用壳层之间的尺寸、滚动和导航边界。

## 常用组件方向

- `Layout`：应用壳层或页面级区域组织。顶层壳层和业务内容区要有明确所有权。
- `Menu`：主导航或局部导航。选中和展开状态应由当前路由与菜单模型推导。
- `Breadcrumb`：从菜单、路由或已声明导航模型推导当前位置，不硬编码易变化的业务事实。
- `Tabs`：同一上下文下的平级视图切换，不用于无关功能之间的主导航。
- `Dropdown`：紧凑承载次要命令，命令语义和禁用状态要明确。
- `Grid`、`Flex`、`Splitter`：组织响应式和可调整布局，优先使用稳定尺寸和明确约束。

## 选择规则

- 应用壳层布局任务必须检查菜单进入、直接地址进入、刷新和局部加载失败。
- 业务页面不要重复应用壳层已经提供的页头、侧边菜单或全局面包屑。
- 修改导航前先确认是否涉及菜单配置、路由模型或路径前缀；如果涉及，按目标仓库契约处理。
- 侧边栏收起、展开和内容区宽度变化不能造成文字重叠或布局跳动。
- 涉及微前端宿主、子应用或挂载区时，使用 `$dy-sec-microfrontend` 确定所有权和集成验证；本 reference 只负责 Ant Design 布局与导航组件。

## 官方资料核对

- 从组件总览定位 Layout、Menu、Breadcrumb、Tabs、Dropdown、Grid、Flex 等组件。
- 对 `Menu` 选中态、展开态和 items 结构不确定时，查看组件级 markdown。
- 对语义结构和样式定制不确定时，查看官方语义文档。

## 应用检查

- 路由路径和菜单路径遵循目标仓库现有规范，不在组件层创造第二套路径格式。
- 应用壳层只放平台或应用级能力，不承载业务页面和业务表单。
- 跨模块跳转使用路由公开能力或标准 URL，不直接操作其他模块内部状态。
