# 应用 UI 规则

## 目标范围

- 应用配置：只处理已声明的应用元数据、菜单、功能开关和装配输入。
- 应用壳层：处理应用级布局、导航、身份入口、加载态、错误边界和监控入口。
- 业务模块：处理业务页面、局部路由、接口调用、局部状态、表单逻辑和业务组件。

目标仓库采用微前端时，宿主与子应用的进一步所有权、生命周期和隔离由 `$dy-sec-microfrontend` 约束；不要在本 reference 中复制架构规则。

## 路由与菜单

- 路由、菜单和路径前缀采用目标仓库声明的单一契约。
- 页面内部跳转不越过所属模块边界；跨模块导航使用公开路由能力或标准 URL。
- 修改导航或壳层时，验证菜单进入、直接地址进入、浏览器刷新和局部加载失败。

## 样式与布局

- 页面样式限定在当前应用或模块作用域，不覆写 `body`、`html` 或其他应用根节点。
- 固定格式区域需要稳定尺寸、最小宽度或响应式约束，防止内容变化导致布局跳动。
- 文本不能遮挡其他元素；长词、中英混排和按钮文字要有换行、截断或自适应策略。
- 页面区块不要层层套卡片；卡片只用于重复项、弹窗和真实需要框定的工具区域。
- 不使用装饰性渐变球、光斑或无信息背景填充操作型界面。

## 组件与交互

- 工具按钮优先使用清晰图标并提供 Tooltip 或可访问名称；React 应用优先 `lucide-react`，缺依赖时提示安装或请求确认，不默认回退到 `@ant-design/icons`。
- 文字排版、说明、弱化信息、省略和可复制文本优先使用 Ant Design `Typography`。
- 组件间距、工具栏排列、表单操作区、列表行操作和局部弹性布局优先使用 Ant Design `Space` / `Flex`。
- 数值使用输入框、步进器或滑块；布尔设置使用开关或复选；多选使用 Select、Checkbox 或 Transfer，并按复杂度选择。
- 加载、空、错误、权限不足、禁用、提交中和成功反馈与主流程一起设计。
- 不在页面里写功能教程式说明；界面通过结构、标签和状态自解释。

## 验证清单

- 目标应用和模块是否明确。
- 是否无意触碰配置、菜单、路径前缀、版本或制品。
- 是否需要应用级集成验证。
- 组件卸载后是否清理计时器、订阅、浮层和临时节点。
- 是否含有内部域名、地址、账号、凭据、本地代理或临时环境信息。
