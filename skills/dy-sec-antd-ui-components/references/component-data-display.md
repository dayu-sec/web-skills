# 数据展示

## 适用任务

- 表格、列表、详情、统计、标签、状态徽标、空状态、加载态、对比和扫描效率优化。

## 常用组件方向

- `Table`：结构化数据、排序、筛选、分页、批量操作。列要服务扫描和比较。
- `List`：同类条目流式展示，适合内容密度较低的重复信息。
- `Descriptions`：详情字段展示。字段较多时分组，但不要做成嵌套卡片堆叠。
- `Statistic`：关键数字和趋势。要配合单位、时间范围和解释来源。
- `Tag`、`Badge`：短状态、分类、数量提醒。颜色语义要稳定。
- `Empty`、`Skeleton`：无数据和加载中状态。空状态要给下一步动作或原因。

## 选择规则

- 表格不是默认答案；少量实体或详情优先用列表、描述或紧凑布局。
- 状态字段必须可读，不只依赖颜色。
- 加载、空、错误、权限不足要和主要数据区共位展示。
- 大量列要优先考虑列顺序、固定列、溢出和响应式，而不是简单缩小字号。

## 官方资料核对

- 从组件总览定位 Table、List、Descriptions、Statistic、Tag、Badge、Empty、Skeleton 等组件。
- 对表格选择、展开、虚拟滚动、分页或列配置不确定时，查看组件级 markdown。

## 应用检查

- 表格筛选、分页和局部缓存属于对应业务模块。
- 应用壳层只提供平台级加载和错误边界，不承载业务数据展示逻辑。
- 文本、数字、状态标签不能互相遮挡，移动端要有明确收缩策略。
