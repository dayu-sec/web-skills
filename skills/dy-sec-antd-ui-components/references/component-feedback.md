# 反馈与状态

## 适用任务

- 异步操作反馈、保存结果、确认、异常、局部加载、空状态、权限不足、流程结果页。

## 常用组件方向

- `Modal`：需要用户集中决策或编辑少量内容。不要把完整复杂页面塞进弹窗。
- `Drawer`：辅助详情、配置或侧向流程，适合保留当前页面上下文。
- `Message`：短暂操作反馈，不承载复杂说明。
- `Notification`：跨区域、较持久的提示，数量要克制。
- `Alert`：页面内可见提示，适合错误、警告和说明性状态。
- `Result`：流程结果、权限不足、加载失败等较完整状态。
- `Spin`、`Skeleton`：等待状态。局部加载优先局部展示，避免整页阻塞。
- `Popconfirm`：低成本二次确认，适合列表行或按钮附近的风险动作。

## 选择规则

- 反馈要贴近触发区域；局部失败不应导致整个后台不可用。
- 失败信息要可恢复，至少说明原因、下一步或重试方式。
- 删除、发布、批量操作等风险动作要有确认和不可逆提示。
- 加载中状态要保持布局稳定，不让按钮、表格、表单跳动。

## 官方资料核对

- 从组件总览定位 Modal、Drawer、Message、Notification、Alert、Result、Spin、Skeleton、Popconfirm。
- 对弹窗可关闭行为、异步确认、通知堆叠或结果页语义不确定时，查看组件级 markdown。

## 应用检查

- 页面或功能模块加载失败时使用局部错误边界降级，不影响其他导航。
- 接口异常、权限不足、登录过期要分别处理，不混成通用失败。
- 卸载时清理弹窗、通知、临时节点和订阅。
