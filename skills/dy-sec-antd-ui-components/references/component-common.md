# 通用控件

## 适用任务

- 按钮、图标按钮、文字排版、组件间距、弹性对齐、分隔、提示、基础操作区。
- 工具栏、表单底部操作、列表行操作、详情页辅助入口。

## 常用组件方向

- `Button`：明确命令和关键操作。主要操作数量要少，危险操作需要二次确认或明确风险提示。
- 图标：用于高频工具按钮、状态提示和紧凑操作。React 应用优先使用 `lucide-react`；未安装时提示按项目包管理器安装或确认是否允许添加依赖。图标按钮必须有可理解名称或 tooltip。
- `Typography`：标题、说明、正文、可复制文本、弱化信息。避免用过大的标题塞进表单、卡片或侧栏。
- `Space` 和 `Flex`：控制横向、纵向间距和对齐。不要用零散 margin 拼接复杂布局。
- `Tooltip`：解释不熟悉的图标或短标签，不承载长说明。
- `Divider`：分隔强相关内容，不把页面切成过多碎片。

## 选择规则

- 能用熟悉图标表达的工具操作，不要做成占空间的文字按钮。
- 文字排版不要默认写裸 `span`；优先用 `Typography.Text`、`Typography.Paragraph`、`Typography.Title` 表达文本层级、省略、复制和弱化语义。
- 组件间距和横纵排列不要默认写裸 `div` 加 margin；优先用 `Space`、`Flex` 或对应组件的 `gap`、`align`、`justify` 能力。
- 只有在 Ant Design 组件无法表达语义、需要接入已有业务容器或需要非常局部的结构钩子时，才写普通 `div` / `span`，并说明原因。
- 破坏性动作、异步提交、不可撤销操作要覆盖确认、加载、成功、失败状态。
- 文案要短，按钮内容不能溢出；长词或中英混排要考虑换行和最小宽度。
- 重复操作区保持顺序一致：主操作、次操作、危险操作分组清晰。

## 官方资料核对

- 从 `official-docs.md` 的本地缓存定位 Button、Typography、Space、Flex、Tooltip、Divider 等组件。
- 对 API、语义结构或示例不确定时，查看对应组件级 markdown。

## 应用检查

- 不引入业务域外状态。
- 不为一个局部按钮修改应用壳层布局。
- 不把说明文字写成可见的功能教程；界面应该直接可操作。
