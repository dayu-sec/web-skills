# OpenAPI、安全与演进

## OpenAPI 真源

- 为每个服务维护一份可验证的 OpenAPI YAML 或由代码确定性生成的等价真源，不同时手工维护两份契约。
- 明确 `openapi`、`info.title`、`info.version`、`paths`、`components.schemas` 和安全方案。
- 为每个操作声明稳定的 `operationId`、标签、概要、详细语义、认证要求、幂等性和副作用。
- 为路径、Query、Header 和 Cookie 参数声明位置、线上名称、必需性、类型、格式、枚举、默认值、范围和示例。
- 为所有实际返回的 `2xx`、主要 `4xx`、`429` 和 `5xx` 声明响应；复用统一错误 schema，但不要隐藏具体状态码。
- schema 明确 `required`、`nullable`、数组元素、日期格式和 `additionalProperties` 策略。
- 示例只使用中性占位数据，不包含真实域名、内部地址、账号、Token、人员或客户信息。

提交前运行仓库约定的 OpenAPI lint，并通过契约测试确认运行时状态码、媒体类型、字段名和错误体与描述一致。生成客户端时把生成差异纳入评审，防止无意破坏兼容性。

## 认证与授权

- 使用请求头传递认证信息，按仓库和平台约定使用 OAuth 2.0、OIDC、签名或服务身份。
- 在入口完成凭据校验，在应用或领域边界校验操作权限、资源归属和租户边界。
- `401` 与 `403` 分开；避免通过错误描述或时序差异泄露受保护资源是否存在。
- 高风险写操作考虑重放保护、请求时间窗、nonce、签名或幂等键。
- 最小化 Token 权限和生命周期，不在 URL、日志、异常或 OpenAPI 示例中暴露凭据。
- CORS 使用精确来源、方法和请求头允许列表；只有确有跨域调用方时启用，不把 `*` 与凭据组合。

## 输入与输出安全

- 对标识、文件名、URL、表达式、排序字段和过滤字段建立允许列表。
- 使用参数化查询和安全客户端，防止 SQL/命令/模板注入、路径穿越和 SSRF。
- 对上传内容限制大小、数量、类型和解析成本；对响应集合、查询复杂度和导出任务设置上限。
- 防止批量赋值：请求 DTO 只声明允许调用方修改的字段，不直接绑定持久化实体。
- 错误响应泛化内部故障，内部日志按数据分类脱敏并控制访问。

## 版本与兼容演进

使用主版本路径 `vN` 表达破坏性版本，例如 `/api/v1/orders`。版本前缀由网关或应用统一管理时保持单一责任。

通常兼容的变更：

- 新增可选请求字段。
- 新增响应字段，但要确认严格客户端是否允许。
- 新增端点或新的可选枚举消费路径。
- 放宽不影响安全和业务约束的输入限制。

通常不兼容的变更：

- 删除或重命名字段、路径或操作。
- 改变字段类型、含义、必需性、空值语义或时间单位。
- 收紧已接受的输入、改变默认排序或分页稳定性。
- 给已有枚举增加客户端无法容忍的新值。
- 改变 HTTP 状态、错误状态、认证方式或幂等行为。

- 先识别调用方和已发布 SDK，再决定原地兼容、弃用或主版本升级。
- 弃用时在 OpenAPI 标记 `deprecated`，提供替代路径、迁移说明和可观察的使用量。
- 兼容分支记录来源、适用版本、监控方式和删除条件；不要永久维护无来源的双字段或双信封。
- 数据库和消息契约的演进与 HTTP 契约分开评估，避免只更新控制器而破坏异步消费者。
