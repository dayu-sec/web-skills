# 资源与 HTTP 语义

## 资源建模

- 先列出资源类型、稳定标识、生命周期和资源间关系，再设计端点。
- 集合路径使用复数名词，例如 `/orders`、`/devices`；没有自然复数形式时保留单数名词。
- 只有子资源离开父资源便失去独立标识或权限边界时才使用嵌套路径，例如 `/orders/{order_id}/items/{item_id}`。
- 独立资源或可属于多个父资源的资源使用顶层集合，并通过 Query 参数表达关联查询。
- 路径不使用尾部 `/`，不把数据库表名、控制器类名或界面层级直接暴露为资源模型。

通用 URL 形态：

```text
/{prefix}/v{major}/{resources}/{resource_id}:{action}
```

前缀和版本由目标仓库统一提供时，不在每个控制器重复硬编码。

## 方法和成功状态

| 方法 | 语义 | 安全 | 幂等 | 常用成功响应 |
| --- | --- | --- | --- | --- |
| `GET` | 获取资源或集合 | 是 | 是 | `200 OK` + 资源 |
| `POST` | 创建资源或触发非幂等操作 | 否 | 否 | `201 Created` 或 `202 Accepted` |
| `PUT` | 完整替换已知资源 | 否 | 是 | `200 OK` + 更新后资源 |
| `PATCH` | 局部更新资源 | 否 | 按协议决定 | `200 OK` + 更新后资源 |
| `DELETE` | 删除资源 | 否 | 是 | `204 No Content` |
| `HEAD` | 获取与 `GET` 对应的响应头 | 是 | 是 | `200 OK`，无响应体 |
| `OPTIONS` | 获取通信选项或允许的方法 | 是 | 是 | `204 No Content` 或约定结果 |

- `201 Created` 应返回创建后的资源，并在可定位时设置 `Location`。
- `202 Accepted` 只表示已受理；返回任务或操作资源的标识、状态和查询位置，不伪装成处理完成。
- `204 No Content` 不携带响应体。
- 批量操作要明确是整体原子、逐项结果还是部分成功，不用模糊的单一布尔值隐藏失败项。

## 自定义动作

当操作无法自然表达为资源创建、替换、局部更新或删除时，才使用自定义动作：

```http
POST /jobs/{job_id}:cancel
POST /devices/{device_id}:restart
```

- 动作用小写动词；多个词使用连字符。
- 优先把长时间操作建模为操作资源，例如创建 `/operations` 后查询其状态。
- 不使用 `/execute`、`/doSomething` 或多层动词路径逃避资源建模。
- 可逆或撤销操作要单独定义语义、权限和幂等行为。

## 幂等与重试

- `GET`、`PUT`、`DELETE` 的重复请求应得到相同资源状态；响应码可以随资源当前状态合理变化。
- 对可能被客户端、网关或消息消费者重试的 `POST`，根据业务风险使用幂等键、自然唯一键或请求去重记录。
- 幂等键要绑定调用方、操作和规范化请求摘要，并设置明确的保存期限与冲突处理。
- 不对非幂等操作进行无条件自动重试；重试前区分连接失败、超时、明确拒绝和未知提交结果。
- 更新冲突使用版本号、ETag/`If-Match`、乐观锁或明确的业务冲突检测，并映射为 `409 ABORTED` 等约定错误。

## 状态码选择

- `400`：语法、格式、必填、范围或前置条件等客户端问题。
- `401`：未认证或凭据无效；不要用于“已认证但无权限”。
- `403`：已认证但无权限访问操作或资源。
- `404`：资源不存在，或为避免泄露而按安全策略隐藏资源存在性。
- `405`：资源存在但不支持该 HTTP 方法。
- `409`：资源已存在、版本冲突、并发状态冲突。
- `429`：配额或速率限制，适用时返回 `Retry-After`。
- `500`：未预期的服务端错误，不暴露内部细节。
- `501`：契约中的能力尚未实现；不要把普通业务不支持映射为 `501`。
- `503`：服务或关键依赖暂时不可用，适用时返回重试提示。
- `504`：网关或代理等待上游超时。

错误状态名与 HTTP 状态的完整映射按 `SKILL.md` 的错误响应资料入口读取；实现时不要让同一业务错误在不同端点漂移为不同 HTTP 状态。
