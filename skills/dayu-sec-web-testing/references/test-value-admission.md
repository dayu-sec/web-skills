# 用例准入

一条用例的价值取决于它失败时是否指向一个真实的用户问题。绿灯数量、文件数量和覆盖率都不是价值。

整体投在哪、哪些类型根本不做，见 [测试边界与投入策略](scope-and-strategy.md)；本文只回答边界之内的某一条该不该写、怎么写。

## 准入三问

新增用例前依次回答，任一问不通过就不要写这条用例。

1. **它守的是高风险的业务规则吗？** 只守业务：外部数据到领域模型的解析、业务规则与状态流转、查询与路由参数的语义、权限与可见性判定、错误分类到用户反馈的映射、边界与降级。渲染结果、交互行为、布局与样式不属于业务——它们的正确性由组件库和浏览器拥有。业务之内还要再过风险这一关：普通 CRUD 与低风险 UI 即便属于业务也不写，判据见 [测试边界与投入策略](scope-and-strategy.md)。
2. **被测对象有可独立调用的入口吗？** 能以确定的输入调用、拿到确定的输出或状态变化的对象（纯函数、解析器、归一化、映射、状态机、匹配与选择逻辑、错误分类、配置解析、Schema 校验）才适合单元用例。只能通过渲染结果或文件内容观察的对象（布局、样式、文案接线、目录组织）不用单元用例守。
3. **它失败时用户遇到什么？** 写得出"某类输入下用户看到错误数据 / 操作失败 / 页面空白"才算通过。写不出，只能说出"代码不长这样了"的，这条用例是噪音。

## 值得测的对象

- **外部输入的归一化**：字段命名风格不一致、数组与字典两种形态、空值与缺省、数字与字符串混用、嵌套结构展开。这类逻辑最容易在后端调整时静默错位。
- **边界与降级**：列表为空、总数与本页行数不一致、分页越界、必填字段缺失、超时与失败响应、未登录与无权限。
- **选择与匹配逻辑**：唯一项自动选中、最长路径匹配、父子展开态推导、权限判定、时区与本地化格式化。
- **错误分类与用户可见反馈的映射**：哪类失败该提示、该降级、该静默重试。
- **数据文件一致性**：配置清单与实现声明对齐。断言的对象是数据文件本身，不是读取它的源码。多语言 JSON 键集对齐不在此范围，见下方「不值得测的对象」。
- **可执行的契约转换**：请求体组装、响应解包、导出文件命名等有明确输入输出的函数。

## 不值得测的对象

- 类名、内联样式、样式文件里的属性文本。
- 某个组件有没有 import 某个库、有没有调用某个 Hook、有没有传某个 Prop。
- 函数签名、参数名、类型注解的文本形状。
- **组件渲染与交互结果**：渲染出的 DOM 结构、`aria-label` 与 `title` 文本、CSS 类名与样式规则、点击与键盘交互、下拉开合、滚动与溢出、焦点顺序。这些是组件库的职责，不是业务仓库的。
- 文件或目录是否存在、命名是否符合某种风格。
- 常量等于它自己的字面量拷贝。
- 框架或库自身的行为——那是上游的用例。本仓库的责任是怎么用它：传参、归一化返回值、失败分类，见 [测试边界与投入策略](scope-and-strategy.md)。
- **普通 CRUD 与低风险 UI**：没有特殊规则的列表查询、字段直传的表单提交、开关控制的显隐。其中的非常规部分（分页越界、并发写冲突、软删除后的可见性、批量部分失败）仍然值得测。
- **多语言 JSON 文件的键集对齐、插值变量一致性、字符集检查**：这些属于 i18n 工作过程，由 `dayu-sec-web-i18n` Skill 在实践中指导开发者同步维护，不写成自动化测试守护。

这些对象不是不重要，而是不该由测试来守。它们的失败形态在别的门禁下更早、更准确地暴露。

## 与其它门禁的分工

| 门禁 | 适合守住 |
| --- | --- |
| 类型检查 | 契约形状、必填与可空、调用方与实现的签名一致性、枚举穷尽 |
| Lint | 禁用 API、依赖方向、命名与导入规则、危险语法 |
| 格式化 | 代码风格，不承担任何语义 |
| 构建 | 模块解析、产物生成、别名与环境变量注入 |
| 自动化测试 | 可独立调用对象的行为、边界与错误分支 |
| 组件库自身的用例 | 组件的渲染输出、交互行为、可访问性属性与样式 |
| 真实运行验证 | 布局、交互、导航、鉴权、请求链路与视觉结果 |
| `dayu-sec-web-i18n` Skill | 多语言文案组织、命名空间对齐、键集同步——属于开发过程指导，不转化为自动化测试 |

同一条约束只放在最早能发现它的那一层。类型能表达的不要写成用例，用例能覆盖的不要只靠人工点检。

## 颗粒度与命名

- 一条用例只断言一个行为；一次断言多个不相关事实时，失败信息无法定位。
- 用例名写"在什么条件下应当得到什么"，不写实现手法与文件名。实现改写而行为不变时，用例名不应需要修改。
- 同一行为的多组输入用数据表驱动，不复制多条近似用例。
- 断言尽量落在返回值与可观察状态上；断言中间过程会把实现细节焊进用例。
