# 持久化与一致性

## 数据模型

- 从领域不变量和查询模式设计表、约束和索引，不从 DTO 机械生成表结构。
- 数据库使用 `snake_case` 等仓库统一命名；Java PO/JPA Entity 使用语言约定并显式映射。
- 用数据库唯一、非空、检查和外键约束保护必须成立的数据不变量，同时在应用边界提供可理解错误。
- 为常用过滤、关联、排序和幂等键建立索引；用执行计划验证，不凭字段名猜索引。
- 审计时间、版本字段和软删除语义统一，避免每个实体自行发明。

## 事务

- 在应用用例入口定义事务，写用例使用 `@Transactional`，纯查询按仓库策略使用 `readOnly = true`。
- 确保事务代理生效：避免同类自调用、非受管对象和错误可见性；必要时拆分协作者。
- 不在长事务内执行不可控网络调用、阻塞等待或大批量 CPU 工作。
- 明确异常回滚规则，不捕获异常后继续提交部分状态；确需部分提交时建模为多个可恢复步骤。
- 数据库提交后才触发依赖已提交数据的异步工作；使用事务事件、outbox 或可靠消息机制。

## 并发与幂等

- 先定义并发不变量和冲突语义，再选择唯一约束、乐观锁、悲观锁、原子更新或分布式协调。
- 默认优先唯一约束和乐观锁；悲观锁只用于短事务和可证明的热点冲突，并固定锁顺序避免死锁。
- 捕获唯一/版本冲突并映射为稳定业务错误，不先查再写却忽略竞态窗口。
- 幂等记录包含调用方、操作、请求摘要、结果和有效期；相同键不同请求返回冲突。
- 多实例调度、恢复扫描和消息消费必须考虑重复执行、抢占和租约过期。

## JPA

- 不把 JPA Entity 直接返回 API；控制关联加载，避免 Open Session in View 隐藏 N+1。
- 对列表查询显式分页和稳定排序；通过 fetch join、EntityGraph、批量加载或投影解决 N+1。
- 谨慎实现 `equals`/`hashCode`，不要依赖未持久化前变化的数据库 ID。
- 批量写入控制 flush/clear 周期和内存，确认 JDBC batch 配置与 ID 生成策略兼容。
- Repository 方法、JPQL 和原生 SQL 都要覆盖空集合、边界和数据库方言测试。

## MyBatis/JDBC

- 使用参数绑定，不拼接用户输入；动态表名、列名和排序字段使用允许列表映射。
- 显式映射列与对象字段，复杂结果不要依赖脆弱的自动映射。
- 批量 SQL 控制参数数量、事务大小和失败恢复；大数据处理使用流式读取或分块。
- 原生 SQL 记录为什么需要、依赖哪些方言和索引，并使用真实数据库验证。

## 缓存

- 先定义缓存所有者、key、TTL、空值、失效和一致性容忍度。
- 更新路径在事务成功后失效或更新缓存，避免数据库回滚后缓存已改变。
- 防止缓存穿透、击穿和雪崩；对热点 key 使用有界并发或单飞机制。
- 不缓存权限敏感结果而忽略调用方/租户维度；不要把缓存当持久化真源。

## 数据库迁移

- 使用 Flyway/Liquibase 等仓库既有工具创建新的版本化迁移，不修改已在共享环境执行的迁移。
- 迁移文件只包含当前 schema 变更，命名和位置遵循仓库约定。
- 评估滚动发布：先扩展 schema，再部署兼容代码，回填数据，最后收紧约束或删除旧列。
- 大表变更评估锁、执行时间、磁盘、回填批次和失败恢复；不要在启动阶段无界阻塞。
- 给新列明确可空性、默认值和历史数据处理；不要用误导性哨兵值代替未知或缺失状态。
- 生产迁移优先前向修复；需要回滚时同时说明代码与数据兼容条件。

## 验证

- 运行迁移从空库创建 schema，并从受支持的上一版本升级。
- 使用目标数据库或 Testcontainers 验证 SQL、约束、锁、时区和大小写行为。
- 对高风险查询检查执行计划、索引命中和数据量边界。
- 对并发写、重复消息、重复请求和事务回滚编写可重复测试。
