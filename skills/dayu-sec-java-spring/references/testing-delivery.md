# 测试与交付

## 测试分层

| 测试 | 目标 | 常用方式 |
| --- | --- | --- |
| 领域单元测试 | 不变量、状态转换、边界值、策略 | JUnit，少量或无 Spring |
| 应用服务测试 | 用例编排、端口调用、事务决策 | JUnit + Mockito/Fake |
| Web 切片测试 | 参数绑定、校验、状态码、JSON、错误体、安全 | `@WebMvcTest`/MockMvc |
| 持久化测试 | 映射、查询、约束、锁、方言 | `@DataJpaTest` + Testcontainers |
| 客户端契约测试 | 请求、响应、超时、错误映射 | WireMock/MockWebServer/契约工具 |
| 集成测试 | Spring 装配、迁移、事务、消息和关键路径 | `@SpringBootTest` + 真实依赖容器 |
| 架构测试 | 包依赖和层次边界 | ArchUnit 或仓库已有检查 |

- 优先测试公开行为和业务不变量，不把覆盖率数字当成唯一目标。
- 每个缺陷修复先添加能稳定复现的回归测试。
- 避免过度 mock 框架和数据访问细节；Fake 必须保持契约语义。
- 测试名称表达前置条件、动作和结果，数据使用中性构造器或 fixture。

## 必测场景

- 正常路径、空集合、最小/最大值、非法枚举、缺失与显式 `null`。
- 资源不存在、未认证、无权限、状态冲突、唯一冲突、限流和未知错误。
- 幂等重复、并发更新、事务回滚、重复消息和异步失败恢复。
- 分页稳定性、最大页大小、排序字段允许列表和无界查询防护。
- 时间区间、UTC/偏移、夏令时边界和数据库时间精度。
- 外部依赖超时、重试耗尽、降级、恢复和返回非约定结构。
- 数据库迁移空库安装、从上一版本升级和生产方言特性。

## 测试环境

- 优先使用 Maven Wrapper/Gradle Wrapper 和仓库固定运行时；没有 wrapper 时使用仓库明确要求的工具版本。
- Vendor-specific SQL、Flyway、锁和 JSON/时间行为使用同类数据库容器，不让 H2 的宽松行为成为唯一验证。
- 集成测试禁用或替换真实消息、邮件、调度和外部初始化，确保测试不会访问生产或共享环境。
- 测试凭据只使用本地短期占位，不提交真实密钥或内部地址。
- 控制时钟、UUID 和随机性，使异步与时间测试可重复，不用长时间 `sleep` 等待。

## 质量门禁

先从 `pom.xml`、wrapper、CI 和 `README` 识别仓库实际命令。常见顺序：

1. 格式或格式检查。
2. 编译与静态分析。
3. 单元与切片测试。
4. 集成、契约与迁移测试。
5. OpenAPI lint 和契约差异检查。
6. `mvn verify` 或仓库定义的完整门禁。

不要凭通用经验声称命令通过；记录实际执行的命令、退出码和关键结果。若私有依赖或外部环境阻塞，先运行仍可执行的局部门禁并准确报告缺口。

## 交付复核

- `git diff` 只包含任务范围内变更，没有生成物、密钥、调试日志和临时文件。
- API、OpenAPI、DTO、错误映射和客户端契约一致。
- 数据库迁移、代码部署顺序和滚动升级兼容。
- 新配置具有默认值/必填校验、部署说明和敏感信息边界。
- 日志、指标、追踪和健康检查覆盖新失败模式。
- 公共入口与复杂业务规则有准确注释，无逐行翻译式注释。
- 测试证明主要风险，而不是只证明 Spring Context 可以启动。

## 评审输出

问题按以下格式报告：

```text
[严重度] 文件:行号 - 问题
触发条件：...
影响：契约 / 数据一致性 / 安全 / 可用性 / 可维护性
依据：仓库契约、测试或框架语义
最小修复方向：...
```

先列可导致错误、数据损坏、安全问题和兼容性破坏的发现，再列测试缺口和可维护性改进。没有发现时也说明检查范围与未验证部分。
