# 重型或高级组件

## 适用任务

- 层级数据、复杂选择、日历、导览、颜色选择、二维码、穿梭框、树形结构、低频但信息密度高的组件。

## 常用组件方向

- `Tree`：层级浏览和选择。层级很深时要考虑搜索、展开策略和性能。
- `TreeSelect`、`Cascader`：层级选择。用于选择路径或分类，不用于普通枚举。
- `Transfer`：左右穿梭选择。适合批量集合管理，但对移动端不友好。
- `Calendar`：日历视图。适合时间分布，不适合普通日期输入。
- `Tour`：一次性引导。不要依赖它解释本该自明的常用功能。
- `ColorPicker`：颜色选择。需要治理色板和主题变量，避免不可控自定义色。
- `QRCode`：展示可扫码信息。要考虑失效、刷新和复制替代路径。

## 选择规则

- 重型组件要先确认是否真的降低复杂度；简单选择不要升级成复杂控件。
- 复杂组件必须覆盖空数据、搜索无结果、加载、禁用和错误状态。
- 移动端或窄屏使用重型组件前，要明确布局降级策略。
- 不默认引入扩展组件库；除非任务明确要求或项目已有约定。

## 官方资料核对

- 从组件总览定位相关高级组件。
- 对性能、虚拟滚动、语义结构、键盘交互或受控模式不确定时，查看组件级 markdown 和语义文档。

## 应用检查

- 复杂交互状态保留在对应业务模块内部。
- 应用壳层只承载平台级引导和导航交互，不承载业务配置流程。
- 复杂组件引入前检查包体积、交互成本和评审范围。
