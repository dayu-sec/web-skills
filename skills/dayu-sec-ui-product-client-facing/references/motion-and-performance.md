## 1. 动效的职责边界

动效只承担三件事：

1. **解释状态变化**：让用户知道刚才发生了什么，什么被改变了。
2. **解释空间关系**：让用户知道内容从哪里来、回到哪里去。
3. **确认操作已被接收**：在结果返回前给出即时反馈。

不承担的事：制造“高级感”、填补等待时间、吸引注意力到无关元素。弹跳、发光呼吸、长转场和入场瀑布流不属于客户端产品的默认方案。

## 2. 时长与曲线

### 2.1 基线取值

| 类别 | 时长 | 曲线 | 适用 |
| --- | ---: | --- | --- |
| 即时反馈 | 150ms | `ease` | Hover、Focus、颜色与阴影变化 |
| 标准转场 | 250ms | `cubic-bezier(0.4, 0, 0.2, 1)` | 展开收起、浮层进出、位移 |
| 大位移浮层 | 300ms | `cubic-bezier(0.4, 0, 0.2, 1)` | 全屏抽屉、移动端页面转场 |

对应 Token：`--transition-fast: 0.15s ease`、`--transition-normal: 0.25s cubic-bezier(0.4, 0, 0.2, 1)`。

### 2.2 规则

- 微交互时长锁定在 **150ms–250ms**。低于 100ms 显得生硬，超过 300ms 会让用户产生拖沓与卡顿感。
- 统一使用 Ease-Out 类型曲线：起步快、收尾缓，给人即时响应的轻快感。进入使用 Ease-Out，退出可略快（150–200ms）。
- 同一交互的进入与退出保持同一曲线族，不混用弹性与线性。
- 动效属性优先使用 `transform` 与 `opacity`；避免动画化 `width`、`height`、`top`、`left` 触发重排。
- 不给同一元素叠加多个不同时长的动画，避免节奏冲突。

## 3. 锚点稳定与布局偏移

顶部锚点固定法则：当卡片、模态框或面板内容在状态或 Tab 切换时发生高度变化，**必须锁定顶边坐标**，仅允许底边顺应内容自然向下扩展。

- **反面模式**：使用上下对称居中对齐，导致每次高度变化时顶部标题与关键信息上下震荡跳跃。
- **正确模式**：容器使用顶部对齐（如 `align-items: flex-start`），保证用户视觉焦点绝对稳定。

其他稳定性规则：

- 展开与收起不改变页面其余部分的位置与滚动锚点。
- 为图片、图表和异步内容预留固定尺寸或宽高比，避免内容到达时挤压布局。
- 加载完成后用骨架屏原位替换，保持最终布局一致，不做整块淡入位移。
- 错误信息出现时在字段下方预留空间或使用不改变布局的呈现方式，避免提交按钮跳动。
- 滚动过程中固定元素（顶部导航、底部行动区）高度保持不变，不做收缩动画导致内容抖动。

## 4. 交互状态与微反馈

每个可交互元素必须定义完整状态，且状态之间的差异可感知：

| 状态 | 表现基线 |
| --- | --- |
| Default | 常态材质与颜色 |
| Hover | 背景加深或使用主色弱底；阴影可略微增强；150ms 过渡 |
| Focus | 主色边框加光晕（`--shadow-active`）；必须键盘可见，不得移除默认焦点样式而不提供替代 |
| Pressed | 主色悬浮值 `--color-primary-hover`；可配合极小位移或阴影收缩 |
| Selected | 实心工作面 + 主色 `1px` 描边 + `--shadow-active`，不加粗硬框 |
| Disabled | 降低不透明度并改为弱化文本色；必须说明禁用原因，鼠标指针明确 |
| Loading | 保持元素尺寸不变，替换内容为指示器并禁用重复提交 |

微反馈规则：

- 反馈必须在 100ms 内开始，让用户确认操作已被接收，即使结果尚未返回。
- 悬浮反馈不得被上方浮层遮挡；元素需要放大反馈时优先采用以中心为原点的等比例膨胀，而不是向单侧扩展。
- 关键动作（提交成功、开通完成）可使用更有温度的插画或轻量动效强化情感连接，但不炫技、不阻断后续操作。
- 反馈不能只依赖颜色变化；同时改变形态、图标或文字。

## 5. 浮层与转场

- 模态框：遮罩淡入 150ms，内容 250ms 从 96% 缩放并淡入；关闭时反向且略快。
- 抽屉：从对应边缘位移进入，250ms；移动端全屏抽屉可到 300ms。
- 下拉菜单与 Popover：150ms 淡入并轻微位移（4–8px），位移方向指向触发元素。
- 遮罩使用背景模糊配合明暗对比，让浮层瞬间从背景中脱离（图底关系法则）。
- 浮层关闭后焦点必须返回触发元素；连续打开多个浮层时不叠加阻塞层级。
- 页面级路由切换默认不使用大幅转场；需要时只用短淡入，避免用户误以为页面卡顿。

## 6. 加载与等待表达

| 等待时长 | 表达方式 |
| --- | --- |
| < 300ms | 不显示任何指示器，避免闪烁 |
| 300ms–1s | 局部指示器或按钮内联加载态 |
| 1s–5s | 骨架屏，保持最终布局结构 |
| > 5s | 显示进度、预计范围或阶段说明，并允许用户离开后返回查看 |

- 骨架屏使用与最终内容一致的块结构与尺寸，不使用与布局无关的通用条纹。
- 骨架的微光动画保持低对比、低频率，不制造闪烁。
- 后台长任务提供可离开的进度表达，不要求用户停留在页面等待。
- 分页与无限滚动保留已加载内容的滚动位置，返回时不重置。

## 7. 渲染与感知性能

性能是体验契约的一部分：任何精致的像素设计，一旦伴随失帧与交互卡顿，其价值都会显著下降。

### 7.1 大批量元素

- 大批量重复元素（矩阵、热力图、火花线、长列表）避免为每个热点重复挂载浮层组件；采用**单一共享浮层**配合事件委托，按需更新内容与位置。
- 高密度图形优先使用轻量矢量图形（如 SVG 基本图元）替代大量嵌套 DOM 节点与组件实例。
- 长列表在真实数据规模下评估是否需要虚拟滚动；引入虚拟滚动后必须重新验证键盘导航、焦点、屏幕阅读器和浏览器内查找。
- 共享浮层与虚拟滚动都不得移除可访问替代：信息必须仍可通过键盘到达并被读出。

### 7.2 材质与合成开销

- `backdrop-filter` 开销较高，只用于浮层与顶部导航等少量固定元素，不用于列表项与大批量卡片。
- 大扩散阴影在大量元素上重复渲染会显著增加合成成本；列表项优先使用弱边界与背景色差替代阴影。
- 避免在滚动过程中触发模糊与阴影的动态重算。

### 7.3 结论表述

- 先定义可感知预算：首屏可见、首次可交互、路由切换、表单提交、图表渲染是否及时。
- 性能结论必须附带目标设备、浏览器、内容规模和测量方式。
- 不写“零延迟”“秒开”或固定帧率结论，除非有对应测量证据。

## 8. 可访问性约束

- 遵循系统减少动效偏好：在 `prefers-reduced-motion: reduce` 下移除位移、缩放和视差，保留必要的不透明度变化与状态提示。
- 动效不得成为传达信息的唯一手段；状态变化必须同时有静态可感知的表现。
- 不使用高频闪烁或快速对比反转，避免诱发不适。
- 自动播放的动画提供暂停能力；轮播不自动切换，或提供明确的暂停与手动控制。
- 焦点在动态内容更新后不得跳到不可预测的位置。

## 9. 验证矩阵

| 检查项 | 方法 |
| --- | --- |
| 时长与曲线 | 检查过渡属性是否统一使用 Token，是否存在超过 300ms 的常规微交互 |
| 锚点稳定 | 切换 Tab、展开收起、加载完成后观察顶部标题与关键信息是否位移 |
| 布局偏移 | 在真实网络与真实图片、图表下观察内容到达时是否挤压布局 |
| 交互状态 | 逐一验证 Default / Hover / Focus / Pressed / Selected / Disabled / Loading，并确认键盘可见 |
| 浮层焦点 | 打开与关闭浮层后确认焦点进入与返回位置正确，Esc 可关闭 |
| 加载表达 | 在限速网络下验证骨架屏、指示器阈值和长任务进度表达 |
| 大批量渲染 | 在真实数据规模下测量交互延迟，并确认共享浮层与虚拟滚动未破坏可访问性 |
| 材质开销 | 检查 `backdrop-filter` 与大阴影是否出现在大批量元素上 |
| 减少动效 | 开启系统减少动效偏好后回归关键流程 |

无法在真实设备、真实数据规模和限速网络下验证时，只能报告静态与构建证据，不能宣称动效与性能验收完成。
