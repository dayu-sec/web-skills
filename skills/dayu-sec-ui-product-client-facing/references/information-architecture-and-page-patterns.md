## 1. 从受众到内容优先级

### 1.1 先建立受众模型

1. 列出受众，区分决策者、执行者和只读访客，不直接为每类受众创建独立导航。
2. 为每类受众记录使用频率、专业程度、进入动机、关键判断、期望动作和最担心的事。
3. 合并动机与动作一致的受众，形成少量稳定入口。
4. 权限差异下沉到数据范围、字段和动作级，不复制整套页面。

客户端受众通常低频访问，缺少持续学习界面的动力。信息架构的目标不是覆盖全部能力，而是让最重要的少数动作始终可见、可理解、可到达。

### 1.2 内容优先级排序

对每个页面按以下顺序排序内容，排序结果直接决定视觉重量与位置：

1. **方位**：这是什么页面，属于谁，数据截止到什么时间。
2. **状态**：当前整体是否正常，是否有需要用户处理的事项。
3. **动作**：用户此刻最可能要做的一件事。
4. **解释**：状态是怎么来的，趋势如何。
5. **明细**：可展开、可跳转的详细数据。

不能落入以上任一层的内容，应移出该页面。

## 2. 视线扫描与首屏

```
        F-型扫描模式 (文本与列表)                     Z-型扫描模式 (概览与首屏)
  ┌───────────────────────────────┐           ┌───────────────────────────────┐
  │ ─────────► (第一优先阅读)      │           │ ─────────► (顶部导航栏扫描)    │
  │ ──►                           │           │           /                   │
  │ ──────► (次要扫描)             │           │          /                    │
  │ ──►                           │           │         /  (对角线扫视)        │
  │ │ (垂直向下快速扫过)            │           │        /                      │
  │ ▼                             │           │ ──────► (底部行动触发)         │
  └───────────────────────────────┘           └───────────────────────────────┘
```

- **F-型模式**：适用于密集列表、内容页与长文本。用户先横向扫过顶部，再沿左侧边缘垂直下滑。设计时把核心标识、状态和时间放在最左侧首要位置，不要把关键信息推到行尾。
- **Z-型模式**：适用于概览页与落地首屏。视线在四角之间交错移动，强调首尾呼应。把品牌与方位放在左上，主行动放在视线终点。

首屏规则：

- 首屏必须回答“我在哪里、我拥有什么、我下一步做什么”，并包含至少一个明确的主行动。
- 首屏不承载全部能力入口；把次要能力交给二级页面与渐进式暴露。
- 首屏高度按最小常见视口验证，关键动作不得需要滚动才能发现。

## 3. 渐进式暴露

- 只在当前步骤展示最关键、最常用的信息，复杂或次要参数收纳到二级页面、抽屉或折叠面板。
- 收纳不等于隐藏：被收纳的内容必须有可见入口、明确标签和状态提示（例如已填写、已应用、有异常）。
- 用户完成核心任务必需的动作永远保留在第一层，不因“简洁”下沉。
- 展开与收起不改变页面其余部分的位置与滚动锚点。
- 分步流程中，每一步只承担一个决策；步骤数可见，允许返回修改且不丢失已填内容。

## 4. 全局信息架构

### 4.1 Shell 层

Shell 只承载跨页面稳定能力：

- 产品与当前身份标识。
- 一级导航与当前项。
- 全局搜索（内容规模确需时）。
- 通知、帮助入口和用户菜单。

不要把页面级动作、筛选器或统计塞进全局顶栏。顶部导航可使用玻璃拟态与背景模糊，但必须保证滚动时文字对比度稳定。

### 4.2 导航层级

- 一级导航表达稳定的内容域，控制在 5–7 项以内（席克定律）；使用用户语言的名词，不使用内部模块名。
- 尽量控制在两层可见导航；更深关系使用页内 Tab、锚点目录或对象链接。
- 当前项使用主色弱底加清晰文字标识，不使用大面积实心填充。
- 面包屑用于层级较深的详情页，帮助用户建立方位并快速返回。
- 折叠侧栏仍保留当前项、图标可访问名称和可发现的展开路径。

## 5. 页面骨架

按任务需要组合以下区域，不要求每页全部出现：

| 区域 | 职责 | 注意 |
| --- | --- | --- |
| 页头 | 标题、方位、数据时间、主操作 | 主操作唯一；标题使用用户语言 |
| 状态摘要 | 当前整体状态与待处理事项 | 每项都要能引出一个动作 |
| 主内容 | 模块化网格、列表、详情或长文本 | 按内容优先级排序，不按后端模块排列 |
| 辅助区 | 相关链接、说明、帮助 | 不与主内容争夺视觉重量 |
| 底部行动区 | 转化按钮、下一步引导 | 长页面可固定，但不遮挡内容 |

页头、主内容和网格共享稳定的对齐线，视线沿连续直线移动（连续性法则）。

## 6. 页面模式选择

| 模式 | 适用场景 | 关键规则 | 不适用 |
| --- | --- | --- | --- |
| 概览 / 仪表盘 | 用户需要快速了解整体状态 | 模块化网格，模块大小不等形成节奏；每个指标提供基线、趋势或下一步 | 需要逐条处理的执行任务 |
| 落地页 | 首次访问、说明价值、引导转化 | Z-型扫描，章节留白 64–80px，每屏一个主张一个行动 | 已登录用户的日常操作 |
| 列表 / 队列 | 浏览与筛选同类对象 | F-型扫描，关键标识与状态置于最左；行内保留一个主要动作 | 对象数量极少时改用卡片或直接详情 |
| 主从详情 | 需要在列表与详情之间频繁切换 | 保持左列选中态与滚动位置；详情标题固定为视觉锚点 | 详情内容复杂到需要独立上下文时 |
| 独立详情页 | 详情内容复杂、需要深链接与分享 | 面包屑建立方位；分区使用页内 Tab 或锚点目录 | 轻量查看，用抽屉即可 |
| 抽屉 | 查看或编辑细节且需保留背景上下文 | 宽度按内容决定；一个阻塞层级内完成，移动端占满宽度 | 需要多步复杂流程时升级为页面 |
| 模态框 | 短确认、单一决策、轻量表单 | 内容一屏可见；禁止模态框内再开模态框 | 长表单、复杂流程 |
| 分步流程 | 开通、配置、申请等线性任务 | 步骤可见、可返回、不丢数据；每步一个决策 | 用户已熟悉且字段很少的任务 |
| 内容 / 文档页 | 说明、帮助、报告与长文本 | 单列，正文宽度 640–760px，行高 1.6，提供目录 | 需要并排比较数据时 |
| 表单页 | 提交信息、修改配置 | 单列优先，实心工作面，字段间距 20px，分组间距 32px | 字段极少时并入模态框 |

模式选择由任务与内容决定，不由视觉潮流决定。模块化网格适合概览与落地页；执行页与表单优先连续对齐的单列结构。

## 7. 常见功能模块

### 7.1 模块化网格

- 每个模块拥有独立的内外边距、圆角与层次，形成清晰的视觉块，提升扫视效率。
- 允许模块大小不一：重要内容占据更大面积，次要内容压缩为小卡片。
- 同一行模块保持等高对齐，避免底边参差。
- 模块数量控制在一屏可理解的范围；超出部分改为二级页面或折叠。

### 7.2 指标与状态卡片

- 只保留影响用户判断的指标；每个数值提供比较基线、时间范围或趋势。
- 数值使用核心指标字阶，标签使用辅助正文；不让标签与数值视觉重量相同。
- 异常指标追加图标与文字说明，并提供指向解释或动作的入口。

### 7.3 列表与卡片

- 关键标识、状态和时间置于扫描路径前部并保持对齐。
- 需要区分风险或类型时，使用左侧竖向语义色指示条配合文字标签，不单独依赖颜色。
- 行内保留一个主要动作，其余进入明确菜单；关键动作不得仅在 Hover 出现。
- 承载带阴影卡片的滚动容器需保留内边距，避免首项阴影被裁切。

### 7.4 表单

- 单列优先；双列仅用于字段相互独立、内容短、阅读顺序明确的情况，窄屏必须降为单列。
- 使用实心工作面，不使用玻璃质感；标签常驻可见，不用占位符替代标签。
- 校验在字段失焦或提交时给出，错误信息紧邻字段并说明如何修正。
- 提交按钮状态明确（默认、加载中、禁用），并说明禁用原因。
- 长表单分组并提供进度感知；底部操作区可固定，但不遮挡最后字段与错误信息。

### 7.5 图表

- 图表必须回答一个问题，标题即问题；不把原始记录直接换成形状。
- 固定 2–3 条主色贯穿全站，色彩承担稳定语义。
- 提供数据时间范围、单位和空数据说明；数据不足时明确说明而非展示空白坐标系。
- 图表旁保留文字结论或可访问的数据表替代。

## 8. 完整状态集合

每个数据区域都必须设计以下状态，缺一不可交付：

| 状态 | 设计要求 |
| --- | --- |
| 加载中 | 使用骨架屏保持最终布局，避免内容跳动；短于 300ms 的加载不显示指示器 |
| 空数据（初次） | 说明这里将出现什么、为什么现在没有、下一步做什么，提供主行动 |
| 空结果（筛选后） | 区别于初次为空，说明当前条件并提供清除或放宽条件的入口 |
| 部分失败 | 说明成功与失败的范围，提供重试失败项的路径 |
| 错误 | 用用户语言说明发生了什么和可以怎么做，不暴露堆栈与内部错误码语义 |
| 权限不足 | 说明需要什么权限、如何获取，不泄漏无权对象的存在与内容 |
| 数据过期 | 显示数据时间并提供刷新入口，不静默替换用户正在阅读的内容 |

## 9. 文案与叙述视角

- 以用户为主体，使用第二人称描述其资产、状态和需要处理的动作，赋予主体感与掌控力。
- 不使用服务方内部视角的第三人称称谓，也不暴露内部流程术语、系统模块名和工单状态机的内部值。
- 动作按钮使用动宾短语描述结果，不使用“确定”“提交”等无信息量文案。
- 错误与风险文案说明对象、范围、后果和恢复路径，语气克制不指责用户。
- 术语在全站保持一致；首次出现的专业名词提供简短解释或帮助入口。

## 10. 响应式与降级

| 断点区间 | 布局策略 |
| --- | --- |
| < 768px | 单列；侧栏改为抽屉；抽屉与模态框占满宽度；控件取 44px 舒适档；页面水平内边距 16px |
| 768–1024px | 模块化网格降为 2 列；主从布局改为列表与详情分页；页面水平内边距 24px |
| 1024–1440px | 完整布局；网格 12 列，间隙 24px；页面水平内边距 32px |
| > 1440px | 内容居中，最大宽度 1200–1440px，两侧保留留白；不把内容拉满视口 |

降级规则：

- 降级时保持内容阅读顺序与视觉重要性一致，不因布局变化改变优先级。
- 移动端保留全部关键动作，不把主行动收进溢出菜单。
- 触控设备自动采用 44px 目标档，不沿用桌面紧凑档。
- 横向内容（宽表格、图表）在窄屏使用独立横向滚动容器，页面本身不产生横向滚动。
