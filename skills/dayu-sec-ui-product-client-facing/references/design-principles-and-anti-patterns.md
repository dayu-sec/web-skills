## 1. 设计对象与证据边界

客户端产品主要服务非专业、低频或中频使用、设备与环境高度不一致的外部用户。首要目标是让用户在极短时间内建立方位感与信任感，理解自己拥有什么、系统发生了什么、下一步该做什么，并在异常时保持安全感。视觉要平静、克制、可信，但不能用装饰性“现代感”掩盖信息层级混乱。

与内部运营后台的区别必须在设计之初确立：

| 维度 | 客户端产品 | 内部运营后台 |
| --- | --- | --- |
| 用户 | 非专业、低频、跨设备 | 经过训练、高频、长时间连续工作 |
| 首要目标 | 信任、理解成本、情绪舒适 | 任务效率、准确性、可控性 |
| 信息密度 | 克制展示，允许多一步跳转 | 允许高密度，追求单屏闭环 |
| 留白与尺寸 | 舒适档，大留白、大圆角 | 紧凑档，紧凑节奏、小圆角 |
| 材质 | 柔和层次，顶层可用玻璃拟态 | 平实工作面，材质极简 |
| 交付判断 | 是否被理解、被安抚、被引导 | 是否更快、更准、更可恢复 |

按以下优先级建立设计依据：

1. 目标项目 `AGENTS.md`、产品规格、真实内容和运行时行为。
2. 当前组件库、设计 Token、已有交互约定和可用性证据。
3. 经确认仍有效的原型原则与用户反馈。
4. 本 Skill 的跨项目基线。

发现文档与实现不一致时，先判断是实现缺陷、文档过期还是有意例外。不要把某个原型的页面名、路由、业务字段、品牌文案、固定抽屉比例或阶段性配色带入共享方案。

## 2. 美学内核

客户端界面的美学核心是四个词：**平静（Calmness）、优雅（Elegance）、信任（Trust）、掌控感（Control）**。

```
                     ┌────────────────────────────┐
                     │   客户端 Modern UI 美学体系  │
                     └──────────────┬─────────────┘
                                    │
       ┌────────────────────────────┼────────────────────────────┐
       ▼                            ▼                            ▼
┌─────────────────┐        ┌─────────────────┐        ┌─────────────────┐
│  冷中性画布 +    │        │  克制微光玻璃拟态 │        │  模块化网格布局   │
│  克制科技蓝      │        │  Restrained      │        │  留白、节奏、     │
│                 │        │  Glassmorphism   │        │  渐进式暴露       │
└─────────────────┘        └─────────────────┘        └─────────────────┘
```

三根支柱互相约束：画布必须足够安静，材质才敢引入透明与模糊；材质保持克制，网格才能靠留白而非硬框分区；网格建立节奏后，强调色只需要极小面积就能完成引导。任何一根失衡，其余两根都会被迫加重视觉重量。

## 3. 核心设计原则

### 3.1 理解成本优先于信息完整

- 首屏只回答三个问题：我在哪里、我拥有什么、我下一步做什么。其余内容下沉到二级页面、抽屉或折叠区。
- 每一个模块都应能说清它改变用户的什么判断或动作；不能回答的模块应删除或合并。
- 宁可让用户多点一步，也不要一次性堆满信息；客户端场景的滚动与跳转成本远低于认知过载成本。

### 3.2 克制的科技蓝

- 使用冷中性画布、高不透明工作面和科技蓝主色建立稳定、可信的现代感。
- 蓝色用于主操作、链接、当前项、焦点和选中态，不铺满侧栏、卡片底色、图表全域和背景光效。
- 拒绝高饱和钴蓝、霓虹青蓝和深海蓝大面积底色：400nm–450nm 高能短波蓝光在长时间注视下容易引发睫状肌紧张与视疲劳，大面积冷蓝在心理上也会传达机械感与被监控感。
- 状态色与品牌蓝分离；若信息本身含有蓝色状态，追加图标和文字避免语义混淆。

### 3.3 材质表达层级，不表达装饰

- 材质的唯一职责是让用户区分“背景、内容、浮层”三层空间。
- 玻璃拟态只用于最顶层的模态框、侧滑抽屉和导航控制塔；主内容区、长文本、表单保持高不透明度。
- 用大圆角与弥散软阴影取代粗黑实线边框与短硬阴影；闭合性法则允许极细微光边框或背景色差替代闭合硬框。
- 不用材质叠加制造“高级感”：连续多层半透明会累积视觉噪点并破坏对比度。

### 3.4 留白是结构，不是剩余空间

- 留白承担分组、节奏和呼吸三种职责；相关元素靠近，不同分组明确拉开至少一个间距档。
- 模块大小允许不等，形成视觉节奏，而不是所有区块等大排列造成的呆板感。
- 大屏不自动把内容拉满宽度；正文与表单受最大阅读宽度约束。

### 3.5 情绪与信任来自可预期

- 关键动作给予明确、及时、有温度的反馈；成功、失败和进行中都必须被表达。
- 涉及用户资产、费用、隐私或不可逆结果的操作，说明对象、范围、后果和撤销路径。
- 文案以用户为主体，使用第二人称描述其资产、状态和待办动作；不暴露服务方内部术语、工单编号语义和第三人称称谓。

### 3.6 可访问性是信任的一部分

- 正文对比度至少满足 WCAG 2.2 AA（正文 4.5:1，大字号 3:1），玻璃拟态与低饱和体系下同样不得妥协。
- 玻璃拟态、阴影和颜色不能作为唯一的状态识别方式，需搭配图标、文字或位置形成冗余编码。
- 所有交互状态（Hover / Focus / Active / Disabled）需有可感知反馈，Focus 态必须满足键盘导航可见性。
- 支持缩放、系统减少动效偏好和粗指针输入；触控目标不因视觉紧凑而缩小。

### 3.7 性能是体验契约

- 先定义用户可感知的预算：首屏可见、首次可交互、路由切换、表单提交、图表渲染是否及时。
- 大批量元素避免为每个交互热点重复挂载昂贵浮层；共享浮层或轻量矢量图形仍需保留可访问替代。
- 不写“零延迟”“秒开”或固定帧率结论，除非有目标设备、内容规模和测量证据。

## 4. 材质与空间深度演进

```
拟物化 (Skeuomorphism) ──► 极简扁平 (Flat 1.0) ──► 新拟物 (Neumorphism) ──► 微光玻璃拟态 (Glassmorphism)
 真实纹理 / 重度质感          彻底剥离层次 / 高试错     双光源同质化凸起         半透明折射 / 克制空间悬浮
```

| 范式 | 物理原理 | 对客户端的价值与限制 |
| --- | --- | --- |
| 拟物化 | 模拟真实材质、纹理与重硬阴影 | 降低初代用户学习成本，但视觉杂讯挤占核心内容注意力，现代客户端不再采用 |
| 扁平化 1.0 | 剥离渐变、阴影与立体感 | 提升信息密度，但可点击性（Affordance）丧失，用户难以分辨可交互元素，试错成本上升 |
| 新拟物主义 | 统一光源下的双向投影，元素从背景挤压或凹陷 | 依赖低对比度阴影区分边界，无障碍表现差，且无法支撑多层浮层；客户端仅作局部点缀 |
| 微光玻璃拟态 | 背景模糊 + 半透明填充 + 边缘微光高光 | 当前阶段最适合客户端：保留空间层次又不厚重，但必须克制且验证对比度 |

玻璃拟态的物理本质固定为三件事，缺一不成立：

1. **背景模糊（Backdrop Blur）**：高斯模糊打散背景细节，保留空间上下文感知的同时消除干扰。
2. **半透明填充（Translucency with Alpha Opacity）**：低饱和透明填充建立轻盈的悬浮面。
3. **边缘微光高光（Border Specular Highlight）**：`1px` 极细高光模拟玻璃切割边缘的光线反射。

## 5. 认知理论到设计判断

理论只用于解释和验证设计判断，不作为给每个页面套用固定版式的理由。

### 5.1 格式塔五法则

| 法则 | 客户端中的可执行判断 | 常见误用 |
| --- | --- | --- |
| 亲密性 | 相关联元素保持极小间距（约 6px），不同分组拉开较大间距（约 24px） | 所有内容等间距，或用卡片套卡片代替分组 |
| 相似性 | 同层级元素严格保持颜色、形状、字阶一致；全站主按钮唯一强调色 | 为“丰富”给同级操作随机配色或样式 |
| 连续性 | 主从布局、侧栏与表单保持连续对齐线，视线沿直线移动 | 每张卡片使用不同内边距和网格，破坏扫描路径 |
| 图底关系 | 用背景模糊遮罩与明暗对比让浮层瞬间脱离背景 | 浮层与背景同明度，用户不确定当前焦点在哪 |
| 闭合性 | 极细微光边框或背景色差即可让人眼识别完整卡片 | 给每个区域画满硬实线边框 |

### 5.2 工效学与决策法则

| 法则 | 表述 | 客户端应用 | 常见误用 |
| --- | --- | --- | --- |
| 席克定律 | 决策时间随选项数量呈对数增加 | 削减冗余选项，单页面与单菜单保持聚焦，复杂功能用渐进式暴露收纳 | 把所有选项一次平铺，或反向把必需能力藏进多层菜单 |
| 菲茨定律 | 到达目标的时间取决于目标的距离与大小 | 可点击区域不低于 36×36px，移动端 44×44px，四周预留 Padding 防误触 | 只扩大图标视觉尺寸，不扩大实际点击框 |
| 视觉层级与重量 | 字重、字阶与色彩饱和度构成视觉重量梯度 | 用位置、字重、字阶三者引导视线首先落在核心信息上 | 靠颜色堆叠制造层级，导致全屏争抢注意力 |
| 渐进式暴露 | 只展示当前步骤最关键的信息 | 次要参数收纳到二级页面、抽屉或折叠面板，同时保持可发现 | 把用户完成任务必需的动作也一并深藏 |
| 识别优于回忆 | 可见提示优于记忆负担 | 使用可见标签、面包屑、当前项、已选摘要和明确文案 | 让用户记住图标含义、隐藏路径或未显示的筛选状态 |
| 系统状态可见 | 用户随时知道系统在做什么 | 展示加载、进度、数据时间、保存状态和结果范围 | 只显示旋转图标、瞬时 Toast 或静默更新 |

### 5.3 色彩心理学与视觉工效学

- **60-30-10 配色法则**：60% 主中性画布，30% 次要结构色，仅 10% 用于主强调色与状态通知。
- **暗色文本的优雅代换**：拒绝物理绝对纯黑，改用深灰蓝或深碳灰，消除高对比度文字的光晕发散（Halation Effect），使长文本阅读平滑。
- **告警节制**：高饱和警告色严格限制在错误与告警状态，防止无差别色彩剥夺导致“告警麻木（Alert Fatigue）”。
- **蓝光负荷**：大面积高饱和蓝作为底色会显著增加长时间注视的眼部负担，科技蓝应以小面积强调而非大面积铺陈的方式使用。

## 6. 传统客户端反模式

| 反模式 | 典型表现 | 替代策略 |
| --- | --- | --- |
| 全盘深色黑客风 | 纯黑底 + 高饱和发光文字常驻 | 默认使用冷中性浅色画布；深色作为经过对比度和长时使用验证的独立主题 |
| 高饱和告警泛滥 | 满屏纯红、纯黄、纯绿边框与标签 | 建立状态强度梯度，只让真正紧急的信息获得最高视觉重量 |
| 科技蓝无边界滥用 | 高饱和钴蓝铺满背景、侧栏、卡片与图表 | 蓝色只承担主操作、当前项和焦点；画布保持冷中性低饱和 |
| 硬质框线切割 | 粗黑实线边框、直角、大面积灰底填充 | 用留白、极细弱边界、背景色差和大圆角表达分组 |
| 极简扁平极端化 | 彻底剥离阴影与层次，全靠字号区分 | 保留可点击性线索：材质层次、Hover 反馈、明确的按钮形态 |
| 过度玻璃化 | 主内容区、长文本、表单全部半透明模糊 | 玻璃质感只保留给顶层浮层，内容区保持高不透明度 |
| 材质层层叠加 | 半透明卡片内再嵌半透明卡片 | 一个视觉层级只使用一种材质，层数不超过背景、内容、浮层三层 |
| 卡片套卡片 | 每级分组都加背景、圆角、边框和阴影 | 用留白、标题、分隔线和对齐表达层级 |
| 全站模块等大 | 所有区块同尺寸铺排 | 允许模块大小不一形成节奏，重要内容占据更大视觉权重 |
| 指标卡片墙 | 每个数字独占卡片，没有趋势、基线或动作 | 只保留影响用户决策的指标，提供比较基线、解释和下一步 |
| 首屏堆满 | 把全部能力、数据和入口平铺在首屏 | 首屏保留方位、核心状态和主动作，其余渐进式暴露 |
| 所有动作都是主按钮 | 一屏出现多个实心强调色按钮 | 每个区域只保留一个主要动作，其余使用次级、文字或菜单 |
| 服务方视角文案 | 用第三人称描述用户及其待办 | 以用户为主体的第二人称叙述其资产、状态和需要协同的动作 |
| 图表随机配色 | 同级图表混用临时代用色 | 固定 2–3 条主色贯穿全站，色彩承担稳定语义 |
| 小于合规的点击区 | 桌面视觉紧凑导致图标按钮点击框过小 | 点击框不低于 36×36px，移动端 44×44px |
| 装饰性动效 | 弹跳、发光、长转场制造“高级感” | 动效只解释状态变化与空间关系，时长控制在 150–250ms |
| 顶部锚点震荡 | 内容高度变化时整块上下跳动 | 固定顶边锚点，仅允许底边顺应内容扩展 |
| 只做成功态 | 无空数据、加载、错误、权限或过期状态 | 为完整状态集合设计说明文案和恢复动作 |
| 视觉完成即交付 | 只看设计稿或构建通过 | 用真实内容、移动设备、弱网、键盘和对比度工具验证 |

## 7. 方案评审问题

### 受众与目标

- 谁会使用，多久使用一次，在什么设备与环境下使用？
- 用户打开页面后最想知道的三件事是什么？首屏是否直接回答？
- 界面文案是否以用户为主体？是否泄漏了服务方内部视角与术语？

### 信息与理解

- 首屏每一项信息会改变什么判断或动作？不能回答的是否应移除或下沉？
- 是否存在用户完成任务必需、却被藏进多层入口的能力？
- 图表是否回答问题，还是只把原始记录换成形状？

### 视觉与材质

- 科技蓝是否承担明确语义，还是成为大面积装饰？强调色是否超出 10% 面积？
- 玻璃拟态是否只出现在顶层浮层？主内容区可读性是否受影响？
- 分组是否靠留白与极细边界完成，还是靠硬框和多层卡片？
- 正文与弱文本的实测对比度是否达标？

### 交互与状态

- 加载、空数据、错误、权限不足、过期和部分失败是否都有设计？
- 关键与不可逆操作是否说明对象、范围、后果和撤销路径？
- 动效是否在解释状态变化？是否存在锚点跳动与布局偏移？

### 验证

- 是否用真实最长文案、长标识、零条和大量内容验证？
- 是否在移动端、触控、缩放、键盘和弱网条件下验证？
- 性能结论是否包含内容规模、设备、浏览器和测量方式？

## 8. 交付判断

一个方案只有同时满足以下条件，才可视为客户端产品 UI/UX 完成：

- 用户在几秒内建立方位感，理解自身状态并找到下一步动作。
- 信息层级清晰，首屏克制，深层能力可发现且不牺牲可达性。
- 科技蓝、材质和留白保持克制，且符合目标项目已确认的主题与组件约定。
- 常见异常有可理解的说明和可操作的恢复路径，关键操作有恰当防护。
- 对比度、焦点可见性、键盘路径和触控目标满足可访问性要求。
- 性能和视觉结论来自真实内容、真实设备与真实网络的验证，而非设计稿印象。
