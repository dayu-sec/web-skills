## 1. 使用方式

本文件给出客户端产品的框架中立视觉与尺寸基线，取值已经明确声明，可直接作为设计与实现起点。先读取目标项目已有 Token 和组件库尺寸，建立语义映射；只有缺失角色时才新增 Token。不要为追求字面相同覆盖组件库内部结构，也不要在页面中复制固定像素与颜色字面量。

本文件拥有客户端产品的科技蓝取值、画布、材质、圆角、阴影、留白节奏、字阶和舒适控件尺寸。目标项目已有设计系统或组件库时先建立语义映射，再补齐缺失角色；出现冲突时以目标仓库已确认规范为准，不保留两套数值。不要把本文件的产品规则写入跨产品基础 Skill，也不要默认复用于内部运营后台。

本基线只定义单一浅色科技蓝外观。多品牌色预设、外观切换和深色主题不在本文件范围内；确有需要时按目标项目单独评审，并重新验证对比度与材质表现。

## 2. 颜色角色

### 2.1 基础角色取值

以下取值构成完整的浅色科技蓝体系，可直接使用；调整时保持角色关系与对比度不变。

| 角色 | 取值 | 使用范围 |
| --- | --- | --- |
| 应用画布 | `#F4F7FC` | 页面背景和大面积留白，冷中性微蓝，拒绝纯白与纯黑 |
| 次级画布 | `#EAEEF5` | 侧栏、页脚、分区背景和弱化区域 |
| 卡片工作面 | `rgba(255, 255, 255, 0.82)` | 卡片与面板，半透明以承接玻璃质感 |
| 实心工作面 | `#FFFFFF` | 长文本、表单、选中卡片等需要最高可读性的区域 |
| 输入控件面 | `rgba(255, 255, 255, 0.70)` | 输入框、选择器等控件底色 |
| 主文本 | `#1E293B` | 标题、正文、关键数据；深灰蓝替代纯黑，消除光晕发散 |
| 次要文本 | `#64748B` | 说明、辅助字段、非选中导航 |
| 弱化文本 | `#94A3B8` | 时间、单位、注解和禁用态；不承载关键任务信息 |
| 主强调色 | `#2563EB` | 主操作、链接、当前项、焦点和选中态 |
| 主色悬浮 | `#1D4ED8` | 主操作的 Hover 与 Pressed |
| 主色弱底 | `rgba(37, 99, 235, 0.12)` | 选中背景、Hover 背景和非阻塞提示 |
| 主色光晕 | `rgba(37, 99, 235, 0.25)` | 焦点环与选中态弥散光晕 |

### 2.2 状态语义色

状态色采用低饱和取值，与品牌蓝在色相环上明确区分，避免用户混淆“品牌强调”与“系统提醒”。

| 语义 | 取值 | 使用范围 |
| --- | --- | --- |
| 危险 / 错误 | `#E05252` | 失败、高风险、不可逆操作提示 |
| 警告 / 中等风险 | `#D69E2E` | 需要关注但不阻断的情况 |
| 成功 / 已完成 | `#558B6E` | 成功结果、健康状态、已归档 |
| 中性 / 进行中 | `#64748B` | 排队、处理中、未开始 |

状态色规则：

- 高饱和状态色只用于需要立即关注的局部信息，不作为整张卡片或整行的常态底色。
- 状态至少使用文字加颜色；关键或密集扫描场景追加图标、位置或形状。
- `--color-primary` 只表示品牌主动作和当前焦点，不兼任成功、警告或危险。

### 2.3 面积控制

遵循 60-30-10 法则：

- **60%** 应用画布与留白，承担平静基调。
- **30%** 工作面、次级画布、边界与中性文本，承担结构。
- **10%** 主强调色与状态色，承担引导与提醒。

一屏内通常只保留一个实心主按钮；导航当前项和选中态使用主色弱底加清晰文字，而不是大面积实心填充。

## 3. 材质与层次

界面只允许三层空间，每层材质固定：

| 层级 | 材质 | 典型元素 |
| --- | --- | --- |
| 背景层 | 不透明冷中性画布，无模糊 | 页面背景、次级分区 |
| 内容层 | 高不透明工作面，弱边界，轻阴影 | 卡片、面板、表单、长文本 |
| 浮层 | 半透明 + 背景模糊 + 微光边框 + 强阴影 | 模态框、侧滑抽屉、下拉菜单、顶部导航栏 |

玻璃拟态实现基线：

```css
backdrop-filter: blur(20px);
background: rgba(255, 255, 255, 0.82);
border: 1px solid rgba(203, 213, 225, 0.65);
```

使用约束：

- 只用于浮层与顶部导航；主内容区、长文本、表单、数据密集区域使用实心或高不透明工作面。
- 半透明层不得嵌套：一个视觉层级只使用一种材质，避免噪点累积与对比度衰减。
- 使用玻璃拟态时必须在真实内容背景上实测文字对比度，不以设计稿的纯色背景为准。
- 需要为不支持 `backdrop-filter` 的环境提供不透明回退，且回退后层级关系仍成立。
- 新拟物主义的双向投影不作为常规方案；确需局部点缀时不得承担唯一的状态或边界识别职责。

## 4. 圆角、边框与阴影

### 4.1 圆角梯度

| Token | 取值 | 使用范围 |
| --- | ---: | --- |
| `--radius-sm` | 8px | 输入框、小按钮、标签、徽章 |
| `--radius-md` | 12px | 内层子模块、列表项、工单式卡片 |
| `--radius-lg` | 20px | 外层大卡片、模态框、抽屉 |
| `--radius-full` | 9999px | 头像、圆形图标按钮、胶囊标签 |

大圆角是客户端柔和感的主要来源，但同一层级只使用一个档位；卡片内元素的圆角必须小于外层卡片。

### 4.2 边框

- 结构边界使用 `1px solid rgba(203, 213, 225, 0.65)`，低透明度、跟随冷中性色相。
- 优先用背景色差和留白划分区域，边框只在闭合性不足时补充。
- 禁止粗实线深色边框；选中态用主色描边加弥散光晕，而不是加粗硬框。

### 4.3 阴影

| Token | 取值 | 使用范围 |
| --- | --- | --- |
| `--shadow-soft` | `0 16px 40px rgba(30, 41, 59, 0.06), 0 2px 8px rgba(15, 23, 42, 0.02)` | 内容层卡片的常态弥散阴影 |
| `--shadow-active` | `0 4px 16px rgba(37, 99, 235, 0.12)` | 选中态与主色相关的发光弥散阴影 |
| `--shadow-overlay` | `0 24px 64px rgba(15, 23, 42, 0.12)` | 模态框、抽屉和下拉菜单等浮层 |

阴影规则：大扩散半径、低不透明度、颜色跟随主文本色相；禁止使用短硬阴影（如 `0 2px 4px #000`）。阴影只表达层级高度，不表达状态。

## 5. 间距系统

### 5.1 基础刻度

使用 4px 微单位和 8px 主节奏。客户端留白整体比内部后台宽松一档。

| 值 | 典型用途 |
| ---: | --- |
| 4px | 图标细节、同组极近关系 |
| 6px | 标签与输入框、图标与短文本等亲密性关系 |
| 8px | 同组控件、常规行内间距 |
| 12px | 卡片内内容块、字段组 |
| 16px | 常规容器内边距、列表项间距 |
| 20px | 内容区块之间的中等节奏 |
| 24px | 卡片内边距、不同分组之间的标准分隔 |
| 32px | 页面区块之间、模块化网格间隙 |
| 40px | 主要章节间隔、空状态上下留白 |
| 48px | 页面主区块分隔、桌面页面垂直节奏 |
| 64px | 落地页章节、大型概览区分隔 |
| 80px | 落地页首屏与章节之间的强留白 |

新增间距优先从这组刻度选择。10px、14px、18px 等值只有在组件库既有尺寸、图标光学对齐或明确几何约束下使用，并沉淀为组件 Token，不在页面中反复出现。

### 5.2 关系映射

| 关系 | 建议值 | 说明 |
| --- | ---: | --- |
| 标签与输入框 | 6px | 亲密性法则，保持字段归属清晰 |
| 输入框与帮助或错误 | 6px | 错误出现时不改变字段归属 |
| 图标与文字 | 8px | 图标与标签形成单一整体 |
| 同一工具组控件 | 8px | 不同工具组使用更大间隔 |
| 表单字段之间 | 20px | 长说明字段可到 24px |
| 表单分组之间 | 32px | 配合分组标题使用 |
| 卡片内内容块 | 12–16px | 标题与正文按层级选择 |
| 卡片内边距 | 24px | 紧凑卡片 16px，落地页大卡片可到 32px |
| 模块化网格间隙 | 24–32px | 桌面取上限，窄屏取下限 |
| 页面区块之间 | 32–48px | 落地页章节可到 64–80px |
| 页面水平内边距 | 16px 窄屏 / 24px 平板 / 32–48px 桌面 | 受最大内容宽度约束，不随视口无限增大 |
| 模态框与抽屉内边距 | 24px | 页头、正文、页脚共享同一对齐线 |

### 5.3 组合规则

- 先用较小间距表达同组，再用至少一个刻度差表达分组；亲密性 6px 与分组 24px 的对比是客户端分组的默认手段。
- 相邻区域已有边界或背景变化时减少额外留白；缺少视觉边界时增加留白。
- 水平排布使用 `gap` 管理，不给每个子项散落左右 `margin`。
- 页头、内容区和模块化网格共享稳定对齐线，不因卡片内边距反复偏移。
- 避免连续三层容器都使用 24px 以上内边距造成有效空间快速缩小。

## 6. 文字系统

### 6.1 字阶

客户端正文基线为 16px，高于内部后台的 14px 生产型基线，以降低非专业用户与移动端的阅读负担。

| 语义 | 字号 / 行高 | 字重 | 使用范围 |
| --- | --- | ---: | --- |
| 注解与元信息 | 12 / 18px | 400 | 时间、单位、脚注；不承载主要信息 |
| 辅助正文 | 14 / 22px | 400 | 次要说明、卡片副文本、表格内文本 |
| 默认正文 | 16 / 26px | 400 | 正文、表单、详情、常规控件 |
| 字段标签 | 14 / 20px | 500 | 表单标签、筛选名称 |
| 强调正文 | 16 / 26px | 500 | 需要强调的关键句、选中项文字 |
| 组件标题 | 18 / 26px | 600 | 卡片标题、列表项标题 |
| 区块标题 | 20 / 30px | 600 | 页面主要分区、详情组 |
| 页面标题 | 24 / 34px | 600 | 页面与对象标题 |
| 核心指标 | 32 / 40px | 600 | 少量概览数值，不用于常规正文 |
| 首屏主标题 | 40 / 48px | 700 | 落地页与营销首屏，桌面专用 |
| 等宽数据 | 14 / 22px | 400–500 | 标识、地址、代码片段 |

### 6.2 排版规则

- 正文不低于 16px，辅助文本不低于 14px，12px 只用于非关键注解；移动端同样遵守。
- 同一组件最多使用 2–3 个字阶，优先通过位置和字重建立层级。
- 正文使用 400，标签常用 500，标题常用 600，仅首屏主标题可到 700；避免 800 字重大面积出现。
- 长文行高取 1.6 左右，标题取 1.2–1.4；不为压缩空间牺牲正文行高。
- 正文最大阅读宽度约 65–75 字符；大屏不把段落拉满容器宽度。
- 中文不通过大写字距或过宽 `letter-spacing` 模拟分组标签；短英文代码可按字体需要微调。
- 数值信息使用一致数字特性；若字体支持，启用等宽数字以稳定对齐。
- 不以颜色作为唯一层级。弱化文本仍必须满足对比度要求，禁用态与只读态不能混淆。

## 7. 控件与目标尺寸

### 7.1 控件高度档位

| 档位 | 高度 | 使用场景 |
| --- | ---: | --- |
| 紧凑 | 36px | 内容密集区域的次级控件、行内筛选、标签切换 |
| 默认 | 40px | 客户端默认标准：表单、按钮、搜索框、选择器 |
| 舒适 | 44px | 移动端、主要转化按钮、独立弹窗表单 |
| 强调 | 48px | 落地页主行动按钮、首屏引导入口 |

同一表单或工具组保持一致高度。使用组件库时映射“紧凑 / 默认 / 舒适”语义并保持整套组件一致，不为获得某个数值单独覆盖组件内部 DOM。

### 7.2 目标尺寸

- 菲茨定律基线：可点击区域不低于 **36×36px**，移动端与触控场景不低于 **44×44px**。
- WCAG 2.2 AA 要求指针目标至少容纳 24×24 CSS px 或满足相邻目标间距例外；本基线把 36px 作为客户端下限，不把 24px 合规最低值当推荐视觉尺寸。参考 [Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) 与 [Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)。
- 相邻可点击目标之间至少保留 8px 间隙；密集图标组保留 12px。
- 扩大点击框而非仅扩大图标视觉尺寸；文字链接的行高本身即构成目标区。

### 7.3 常用控件

| 控件 | 建议尺寸 | 补充规则 |
| --- | --- | --- |
| 文本输入、选择器、日期控件 | 高 36 / 40 / 44px | 同一表单统一档位；水平内边距 12–16px；圆角 `--radius-sm` |
| 按钮 | 高 36 / 40 / 44 / 48px | 水平内边距 16–24px；图标与文字间距 8px；圆角 `--radius-sm` |
| 图标按钮 | 视觉图标 18–20px，按钮框 36 / 40 / 44px | 提供可访问名称和 Tooltip；不只扩大 SVG |
| 多行文本 | 最小高 96–120px | 支持纵向调整或按内容增长；显示字数时预留空间 |
| 复选框、单选框 | 视觉 18–20px，交互框至少 36px | 标签与控件共同可点击 |
| 开关 | 视觉约 36–44 × 20–24px，交互框至少 36px | 标签说明当前能力，状态不只写在颜色上 |
| 分段控件、Tab | 高 40–44px | 选中态、焦点和滚动行为清晰 |
| 菜单项 | 高 40px | 图标、文字和辅助说明对齐 |
| 标签、Badge | 高 24–28px，字号 12–14px | 若可点击，外层目标提升到至少 36px |
| 头像 | 32 / 40 / 48px | 圆形，提供替代文本 |

## 8. 常见模块尺寸

### 8.1 Shell 与页面

| 区域 | 建议范围 | 说明 |
| --- | ---: | --- |
| 顶部导航栏 | 64px | 客户端取舒适档，可使用玻璃拟态；移动端 56px |
| 展开侧栏 | 240–280px | 文案不截断为首要判断，可允许用户折叠 |
| 折叠侧栏 | 64–72px | 图标点击区和当前态完整，提供可访问名称 |
| 页头 | 最小 72–96px 内容高度 | 标题、状态和主操作对齐，不固定无意义空白 |
| 最大内容宽度 | 1200–1440px | 超宽屏居中并保留侧边留白，不把内容拉满 |
| 正文阅读宽度 | 640–760px | 长文本与表单单列时受此约束 |

### 8.2 卡片、抽屉与模态框

- 常规卡片内边距 24px；紧凑卡片 16px，落地页大卡片可到 32px。
- 小型确认模态框 400–480px，常规表单模态框 520–640px；更复杂内容升级为抽屉或独立页面。
- 窄详情抽屉 400–480px，中等编辑抽屉 480–640px，复杂详情 640–960px，并受视口最大宽度约束。
- 抽屉宽度根据内容、视口和是否需要保留背景上下文决定，不把固定 `vw` 比例或黄金比例当默认规则；移动端抽屉占满宽度。
- 模态框和抽屉的页头、正文、页脚使用同一 24px 对齐线；正文只保留一个主要滚动容器。

### 8.3 模块化网格

- 桌面使用 12 列栅格，间隙 24–32px；模块可跨不同列宽形成节奏。
- 允许卡片大小不一，但同一行的卡片保持等高对齐，避免底边参差。
- 平板降为 2 列，移动端降为单列；降级时保持模块阅读顺序与视觉重要性一致。
- 网格模式适用于概览与落地页；表单、长文本和线性流程仍使用连续单列。

## 9. 组件规范

| 组件 | 规范要点 |
| --- | --- |
| 卡片 | 圆角 `--radius-lg`；常态使用 `--shadow-soft`；选中态改为实心白底 + 主色 `1px` 描边 + `--shadow-active`，不加粗硬框 |
| 列表项卡片 | 需要风险或类型区分时，左侧使用 4–5px 竖向语义色指示条（绝对定位、贯穿卡片全高），配合文字标签，不单独依赖颜色 |
| 滚动容器 | 承载带阴影卡片的滚动容器需保留 4px 内边距，确保首项在 `scrollTop = 0` 时上边框与弥散阴影完整显示，不被裁切 |
| 按钮 | 明确 Default / Hover / Pressed / Focus / Disabled / Loading 六态；一屏一个实心主按钮，其余为次级、描边或文字按钮 |
| 输入框 | 使用 `--bg-input` 底色与弱边界；Focus 态使用主色边框加 `--shadow-active` 光晕；错误态同时改变边框色并显示文字说明 |
| 标签与徽章 | 低饱和底色（语义色 12% 透明度）+ 深色文字，保证可读性；状态色仅用于真正需要提醒的场景 |
| 表单 | 保持高不透明度，不使用玻璃质感；标签与输入框间距 6px，字段间距 20px，分组间距 32px |
| 图表 | 折线关闭圆点标记，使用平滑曲线，线宽 3px；主指标 `#2563EB`、次指标 `#558B6E`，面积渐变自 35% 透明度过渡到 1%；同级图表禁止混用临时代用色 |
| 空状态 | 提供说明文案、成因和一个明确的下一步动作；上下留白 40–64px |

## 11. 视觉验证

### 11.1 源码与组件层

- 定向搜索任意字号、间距、圆角、阴影和颜色字面量，确认它们是必要例外还是应映射 Token。
- 检查同一表单和工具组是否混用不同高度或字体基线。
- 检查 Hover、Focus、Active、Disabled、Read-only、Error 和 Loading 是否改变布局。
- 检查半透明与 `backdrop-filter` 是否出现在内容层或发生嵌套。

### 11.2 浏览器层

- 使用目标浏览器检查 DOM、computed style 和 `getBoundingClientRect()`，验证实际字号、行高、点击框、对齐和滚动容器。
- 用对比度工具在真实内容背景上实测主文本、次要文本、弱化文本、链接和状态文字，而非在纯色设计稿上估计。
- 覆盖 100% 与放大缩放、窄窗口、移动端视口、长中文、长英文标识、空值、错误和多行内容。
- 验证带阴影卡片在滚动容器边缘是否被裁切，固定页头与抽屉是否遮挡焦点或最后一项内容。
- 检查科技蓝面积是否超出 10% 强调预算，状态色强度是否过载，以及主色是否替代了状态语义。
- 验证点击框而非仅图标视觉尺寸；相邻小目标不得依赖肉眼估计间距。

无法使用目标浏览器和真实设备时，只能报告静态与构建证据，不能宣称尺寸、对比度或视觉验收完成。
