# DayuSec 客户端产品 UI

## 工作顺序

1. 读取目标仓库 `AGENTS.md`、产品规格、现有主题和真实页面，确认受众身份、使用频率、专业程度、决策场景、设备构成和当前组件库；原型只作为证据，不覆盖已确认的项目事实。
2. 确认目标属于面向外部客户或终端用户的产品；本 Skill 独立拥有此类产品的科技蓝取值、材质、留白尺寸和页面模式，不把这些结论提升为跨产品基础设计语言，也不套用到内部运营后台。
3. 设计方向、方案评审或旧界面改造时，读取 [设计原则与反模式](references/design-principles-and-anti-patterns.md)，先明确信任、平静、易理解和掌控感目标。
4. 处理首屏、概览、模块化网格、主从详情、引导流程、表单、内容页或状态页时，读取 [信息架构与页面模式](references/information-architecture-and-page-patterns.md)，按受众认知负荷选择模式，不按后端模块或视觉潮流套模板。
5. 建立或调整配色、材质、圆角、阴影、间距、字阶和控件尺寸时，读取 [科技蓝视觉与材质基线](references/visual-system-and-materials.md)；先映射目标项目已有 Token，再新增缺失角色。
6. 处理动效、微交互、加载与骨架、图表渲染或大批量元素性能时，读取 [动效与感知性能](references/motion-and-performance.md)。
7. 按实际技术栈追加最小实现 Skill；不要为套用本规范替换已满足任务需求的组件库，也不要在页面中散落任意像素值和颜色字面量。
8. 用真实文案、长内容、空数据、错误、弱网、移动端和键盘路径验证任务；同时检查对比度、焦点可见性、缩放、触控目标和布局稳定性。

## 决策原则

- 首要目标是让用户在几秒内理解“我在哪里、我能做什么、下一步是什么”，而不是一次展示全部信息；宁可多一步跳转，也不堆满首屏。
- 用冷中性画布、克制科技蓝和柔和材质建立平静与信任；蓝色只承担品牌主操作、当前项和焦点，不大面积铺满背景、卡片与装饰光效。
- 材质服务于层级而非装饰。玻璃拟态、背景模糊和弥散阴影只用于顶层浮层，主内容区、长文本和表单保持高不透明度与稳定可读性。
- 按 60-30-10 控制强调色面积；状态色与品牌蓝在色相上明确区分，且状态不能只靠颜色表达。
- 以用户为主体叙述界面文案，使用第二人称描述其资产、状态和待办动作，不使用服务方内部视角的第三人称称谓。
- 客户端受众低频、非专业、设备多样，交互目标、字号和留白取舒适档；不能借用内部后台的紧凑密度换取信息量。
- 视觉完成不等于体验完成。必须验证信息可理解、动作可发现、状态可恢复、对比度达标，以及真实内容与真实网络下的稳定表现。

## 引用入口

- [设计原则与反模式](references/design-principles-and-anti-patterns.md)：受众定位、美学内核、认知心理学法则、材质演进、传统客户端反模式和评审问题。
- [信息架构与页面模式](references/information-architecture-and-page-patterns.md)：视线扫描、渐进式暴露、导航、模块化网格、主从详情、引导、表单、内容与完整状态集合。
- [科技蓝视觉与材质基线](references/visual-system-and-materials.md)：颜色角色取值、材质与层次、圆角与阴影、间距、字阶、控件与目标尺寸、组件规范和 Token 骨架。
- [动效与感知性能](references/motion-and-performance.md)：动效时长与曲线、锚点稳定、交互状态、加载表达、图表与大批量元素渲染策略。

## 输出要求

- 说明目标受众、使用频率、核心决策、设备构成及选用的页面和交互模式，区分项目事实、原型参考和本 Skill 基线。
- 列出复用或新增的语义 Token 及间距、字阶、圆角、阴影、控件尺寸；说明偏离基线的品牌或组件库原因。
- 指出避免或移除的传统客户端反模式，并报告对比度、键盘与焦点、触控目标、移动端、真实内容和感知性能的验证证据。
- 未进行真实浏览器、移动设备、真实内容量或弱网验证时，明确标注验证边界，不以静态源码、设计稿或构建成功代替运行时结论。
