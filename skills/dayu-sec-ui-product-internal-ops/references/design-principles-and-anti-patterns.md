## 1. 设计对象与证据边界

内部运营和管理后台主要服务经过训练、使用频率高、连续工作时间长的用户。首要目标是让用户快速、准确、可控地完成任务，并在异常、权限受限或数据变化时保持信心。视觉要专业、平静、耐看，但不能牺牲任务效率换取装饰性“现代感”。

按以下优先级建立设计依据：

1. 目标项目 `AGENTS.md`、产品规格、真实权限和运行时行为。
2. 当前组件库、设计 Token、已有交互约定和可用性证据。
3. 经确认仍有效的原型原则与用户反馈。
4. 本 Skill 的跨项目基线。

发现文档与实现不一致时，先判断是实现缺陷、文档过期还是有意例外。不要把某个原型的页面名、路由、业务字段、品牌文案、固定抽屉比例或阶段性配色带入共享方案。

## 2. 核心设计原则

### 2.1 任务优先于系统结构

- 围绕“用户要完成什么”组织入口、数据和动作，不照搬服务、数据库表或组织部门。
- 用少量稳定工作台承载可闭环的任务流；角色通过默认落地页、权限和视图差异进入合适工作台。
- 让任务的开始、当前状态、下一步和完成条件在同一上下文内可理解。

### 2.2 分层密度优先于单纯压缩

- 高密度页面先减少重复标签、无效卡片、过宽留白和低价值信息，再考虑紧凑尺寸。
- 使用位置、对齐、字重、字阶、色彩强度和间距建立主次，不让所有信息拥有相同视觉重量。
- 提供紧凑与默认密度时保持信息语义和操作位置稳定，避免切换密度后重新学习页面。

### 2.3 可控性优先于自动化表演

- 明确展示筛选范围、选中范围、数据时间、执行对象、权限和操作结果。
- 自动刷新、智能建议、批量处理和乐观更新必须提供暂停、确认、撤销或恢复路径。
- 不在用户编辑、选择或阅读时静默替换数据、移动行或重置滚动位置。

### 2.4 稳定优先于视觉跳变

- 保持页头、工具栏、选中项和详情标题等视觉锚点稳定。
- 为加载、错误、展开和动态内容预留空间，避免操作按钮、焦点和阅读位置来回跳动。
- 动效只解释状态变化和空间关系，不用弹跳、发光或长转场制造“高级感”。

### 2.5 速度与准确性共同构成效率

- 高频、低风险、可逆操作减少点击和确认，支持批量、键盘或最近使用路径。
- 低频、高风险、不可逆操作增加影响说明、权限校验、确认和审计。
- 不用统一弹窗或统一二次确认覆盖所有动作；按风险和可逆性分级。

### 2.6 性能是交互契约

- 先定义用户可感知的预算：首次可操作、筛选反馈、翻页、展开详情、批量提交和自动刷新是否及时。
- 大数据量的检索、加载和结果范围策略要由真实规模驱动，并验证键盘、屏幕阅读器、选择和定位不被破坏。
- 避免为大量交互热点重复挂载昂贵浮层；共享浮层或轻量图形仍需保留可访问替代。
- 不写“零延迟”“秒开”或固定帧率结论，除非有目标设备、数据量和测量证据。

### 2.7 可访问性是专业效率的一部分

- 保留语义结构、可见焦点、合理 Tab 顺序和完整键盘路径。
- 状态、风险、选中和禁用不得只依赖颜色；使用文字、图标、位置或形状形成冗余编码。
- 支持缩放、系统高对比设置、减少动效和粗指针输入；紧凑桌面布局不能成为小点击区的借口。

### 2.8 克制的科技蓝

- 使用冷中性画布、清晰工作面和科技蓝主色建立稳定、可信的专业感。
- 蓝色用于主操作、链接、当前项和焦点，不大面积铺满侧栏、卡片、图表和装饰光效。
- 状态色与品牌蓝分离；若信息本身含有蓝色状态，增加图标和文字避免语义混淆。

## 3. 认知理论到设计判断

理论只用于解释和验证设计判断，不作为给每个页面套用固定版式的理由：

| 理论或原则 | 后台中的可执行判断 | 常见误用 |
| --- | --- | --- |
| 接近性 | 标签靠近所属字段，同一工具组使用小间距，不同区块至少拉开一个间距档 | 所有内容等间距，或用卡片套卡片代替分组 |
| 相似性 | 同一语义的按钮、状态、字段和链接保持一致外观 | 为了“丰富”给同级操作随机颜色或样式 |
| 连续性与对齐 | 让页头、工具栏、列表项目、表单标签和详情内容共享稳定对齐线 | 每张卡片使用不同内边距和网格，破坏扫描路径 |
| 图底关系 | 使用工作面、遮罩、边界和焦点把当前任务与背景分开 | 只靠透明模糊或大阴影制造层级，降低可读性 |
| 选择复杂度 | 对大量选项分组、搜索、提供合理默认和最近使用 | 把所有选项隐藏进“更多”，或一次平铺全部选项 |
| 目标可达性 | 高频动作靠近作用对象并提供足够目标区；危险动作避免紧邻常用动作 | 只缩短鼠标距离，不考虑误触、键盘和触控 |
| 识别优于回忆 | 使用可见标签、面包屑、筛选摘要、历史和快捷键提示 | 让用户记住图标、隐藏路径、代码或未显示的筛选状态 |
| 渐进式暴露 | 首屏保留当前决策所需内容，低频细节下沉但保持可发现和可固定 | 把专业用户的高频能力永远藏到多层抽屉 |
| 系统状态可见 | 展示加载、数据时间、连接、进度、结果范围和保存状态 | 只显示旋转图标、瞬时 Toast 或静默自动更新 |
| 防错与恢复 | 按风险选择约束、预览、确认、撤销、版本和回滚 | 对所有操作弹同一句确认，或完全依赖用户谨慎 |

这些原则需要结合频率、风险、数据规模和输入方式权衡。例如，减少选项可以降低选择复杂度，但不能删除专业用户完成任务必需的能力；增大目标可以减少误触，但紧凑桌面工作面仍需保持合理信息密度。

## 4. 传统后台反模式

| 反模式 | 典型表现 | 替代策略 |
| --- | --- | --- |
| 一角色一套菜单 | 新角色复制完整导航，入口随组织结构增长 | 建立稳定任务工作台，角色只改变默认入口、能力和数据范围 |
| 按后端模块组织导航 | 用户在多个模块之间拼接一个任务 | 按任务阶段组织页面，在需要时链接底层对象 |
| 大而全总控首页 | 登录后平铺所有入口、图表和数字 | 按角色落到最常用任务，首页只保留可行动的概览与待办 |
| 指标卡片墙 | 每个数字独占卡片，没有趋势、阈值或动作 | 只保留影响决策的指标，提供比较基线、异常原因和下一步 |
| 所有页面 Bento 化 | 工作台、表单和执行视图都拆成不等宽卡片 | 概览才考虑模块网格；执行页优先连续对齐和稳定工作面 |
| 卡片套卡片 | 每级分组都加背景、圆角、边框和阴影 | 使用留白、标题、分隔线和对齐表达层级 |
| 全盘深色黑客风 | 纯黑底、高饱和蓝光、发光边框常驻 | 默认使用冷中性浅色；深色作为经过对比度和长时使用验证的主题 |
| 告警色泛滥 | 红、黄、蓝满屏竞争注意力 | 建立状态强度梯度，只让真正紧急信息获得最高视觉重量 |
| 所有动作都是主按钮 | 工具栏和每行都有多个实心蓝按钮 | 每个任务区域只保留一个主要动作，其余使用次级、文字或菜单 |
| 用极小字号换密度 | 10–11px 承载关键字段与说明 | 正文保持 13–14px，先删除冗余和优化信息层级 |
| 隐藏式操作 | 关键动作只在 Hover 出现，键盘和触控不可发现 | 保留常用动作或明确菜单入口，Hover 只补充提示 |
| 固定比例万能抽屉 | 所有详情都使用同一 `vw` 宽度 | 根据任务复杂度、上下文保留需求和视口选择抽屉、模态框或完整页面 |
| 模态框堆叠 | 在弹窗中再开弹窗，用户丢失上下文和退出路径 | 一个阻塞层级内完成任务，复杂流程升级为抽屉或页面 |
| 筛选藏在高级入口 | 高频条件每次都要展开或重新输入 | 常用条件常驻，高级条件可展开、可保存且显示已生效数量 |
| 无差别二次确认 | 所有操作都弹“确定吗”，用户机械确认 | 仅对高风险或难以撤销动作确认，并说明对象、范围和后果 |
| 自动刷新打断任务 | 可见项目顺序变化、选择丢失、详情被替换 | 标记新数据并允许用户刷新，保留选择、滚动和编辑状态 |
| 只做成功态 | 无空数据、无结果、部分失败、权限不足或过期状态 | 为完整状态集合设计下一步和恢复动作 |
| 视觉完成即交付 | 只看截图或构建通过 | 用真实任务、数据、权限、缩放、键盘和浏览器几何验证 |

## 5. 方案评审问题

### 用户与任务

- 谁每天使用，谁偶尔审批，谁只读？不同角色是否真的需要不同页面？
- 用户进入页面后最常做的三个任务是什么？是否能看到起点、当前状态和下一步？
- 高频动作是否比低频设置更靠近数据和焦点？

### 信息与决策

- 首屏每一项信息会改变什么决策或动作？不能回答的内容是否应移除或下沉？
- 状态、优先级、时间和对象是否位于扫描路径前部，并保持对齐？
- 图表是否回答问题，还是只把原始记录换成形状？

### 操作与风险

- 选择范围、批量范围和跨页语义是否明确？
- 失败、部分成功、超时、数据过期和权限变化后如何恢复？
- 高风险操作是否说明对象和影响？可逆操作是否优先提供撤销？

### 视觉与密度

- 页面是否通过过多边框、阴影、卡片和颜色争夺注意力？
- 正文、控件和点击区是否因“紧凑”低于基线？
- 科技蓝是否承担明确语义，还是成为大面积装饰？

### 验证

- 是否用真实最长文案、长标识、零条和大量数据验证？
- 是否完成键盘、缩放、焦点、滚动和弹层回收检查？
- 性能结论是否包含数据规模、设备、浏览器和测量方式？

## 6. 交付判断

一个方案只有同时满足以下条件，才可视为内部运营 UI/UX 完成：

- 用户能快速定位并闭环完成核心任务。
- 数据层级、状态、范围和下一步清晰，且不会因自动更新或布局跳动丢失上下文。
- 常见异常有可操作的恢复路径，高风险操作有恰当防护。
- 密度、科技蓝和视觉层级保持克制，并符合目标项目已确认的主题与组件约定。
- 键盘、焦点、缩放、语义和目标尺寸满足可访问性要求。
- 性能和视觉结论来自与风险相称的真实验证，而非原型印象。
