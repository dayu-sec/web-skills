## 1. 交互设计基线

### 1.1 同时服务发现与熟练

- 所有核心能力都提供可见入口和清晰文案，新用户无需记忆快捷键或猜测 Hover。
- 高频能力可以追加快捷键、命令面板、最近使用、保存视图和批量操作。
- 在菜单或 Tooltip 中展示快捷键，允许冲突处理和关闭；快捷键不能劫持输入框的常用编辑操作。

### 1.2 渐进式暴露但不深藏

- 首屏展示当前决策所需信息，低频参数放入高级区、侧面板或后续步骤。
- 专业用户高频使用的“高级”条件应可固定、保存或恢复，不能每次重新展开。
- 显示隐藏内容的状态，例如“已应用 3 个高级条件”，而不是让结果变化没有可见原因。

### 1.3 保持直接操纵的连续性

- 操作后保持合理焦点、滚动、选择和过滤上下文。
- 行内操作更新局部区域；跨对象或跨步骤任务使用明确导航。
- 动态内容变化不得把键盘焦点移动到不可预测位置。

## 2. 筛选、选择与批量操作

### 2.1 搜索与筛选

- 文本搜索允许适当防抖并显示加载；精确条件变化可以即时生效或统一“应用”，但页面内保持一致。
- 筛选条件使用用户语言，不暴露接口字段名；选项数量大时提供可搜索选择器。
- 已应用条件以可读形式展示，并提供单项移除、全部清除和恢复默认。
- 需要分享、刷新或返回的工作台把筛选、排序、页码和视图写入 URL 或等价可恢复状态。
- 预估查询昂贵时显示范围和时间成本，不让每次按键触发不可控请求。

### 2.2 选择范围

- 清楚区分当前页选择、当前筛选结果全选和所有数据全选。
- 批量栏始终显示已选数量、范围和可用动作；数据更新后说明哪些选择失效。
- 跨页选择需要持久集合或服务器端选择语义，不用当前 DOM 行数冒充全量。
- 用户修改筛选时，明确保留还是清除选择；高风险场景默认重新确认范围。

### 2.3 批量操作

1. 选择对象并持续显示范围。
2. 仅展示对当前选择真正可用的动作，禁用时说明原因。
3. 在执行前展示动作、对象数量、不可处理项和影响。
4. 执行中提供整体进度、取消能力或后台任务入口。
5. 完成后区分成功、跳过、失败和未知，支持失败项重试或导出。
6. 保留审计标识或结果链接，避免只显示瞬时 Toast。

## 3. 异步任务与完整状态

### 3.1 状态集合

为每个数据区域和操作至少判断以下状态是否适用：

| 状态 | 用户需要知道 | 推荐反馈 |
| --- | --- | --- |
| 初次加载 | 正在加载什么 | 保留页面骨架，使用有边界的 Skeleton 或进度 |
| 后台刷新 | 旧数据是否仍可用 | 保留内容，显示非阻塞刷新状态和数据时间 |
| 成功 | 操作结果和影响 | 就地更新并给出简短状态；重要任务提供结果入口 |
| 初次空数据 | 为什么为空、如何开始 | 解释条件并提供创建、导入或了解入口 |
| 筛选无结果 | 哪些条件导致无结果 | 显示条件并提供清除或调整入口 |
| 局部错误 | 哪个区域失败 | 其他区域继续可用，局部重试 |
| 整页错误 | 页面为何不可用 | 错误摘要、重试、返回或支持路径 |
| 部分成功 | 哪些成功、哪些失败 | 分组明细、失败项重试和导出 |
| 数据过期 | 当前信息何时产生 | 时间戳、过期原因和刷新入口 |
| 离线或连接中断 | 操作是否已提交 | 连接状态、待同步项和恢复策略 |
| 权限不足 | 缺少什么能力 | 原因、可见范围、申请或返回入口 |
| 会话过期 | 未保存内容是否保留 | 登录恢复、草稿保护和明确风险 |

状态消息不应无故抢走焦点。对不改变上下文的加载、结果数量、保存成功或错误摘要使用可被辅助技术感知的状态区域。

### 3.2 加载与提交

- 延迟很短的局部请求避免立即闪烁 Skeleton；超过感知阈值再显示稳定反馈。
- 提交按钮在请求期间防重复执行，但仍显示明确进行中状态。
- 可取消任务提供取消；不可取消任务说明离开页面是否继续。
- 后台任务提供任务中心、通知或可返回的任务标识，不要求用户一直停留。

### 3.3 乐观更新

- 只对低风险、可逆且失败易理解的操作使用乐观更新。
- 高风险、跨系统或有审批语义的操作等待服务端确认。
- 乐观更新失败时恢复旧状态、说明原因并保留用户上下文。

## 4. 危险操作与可逆性

按“影响范围 × 可逆性 × 可发现性”决定防护强度：

- **低风险且可逆**：直接执行，提供撤销或历史恢复。
- **中风险或影响多个对象**：执行前摘要范围和变化，使用明确确认文案。
- **高风险或不可逆**：说明对象、数量、依赖和后果；必要时要求输入对象标识、重新认证或审批。

确认框必须使用具体动词，避免“确定 / 取消”独占语义。不可通过把危险按钮做得很小、藏进菜单或降低对比度来防误触。

优先提供软删除、版本、草稿、回滚和撤销；二次确认不能替代可恢复的系统设计。

## 5. 弹层与上下文

### 5.1 模态框

仅用于需要在继续主流程前完成的简短决策或输入：

- 打开时把焦点置于合适的标题、说明或首个控件。
- `Tab` 和 `Shift+Tab` 保持在模态框内，`Escape` 按风险允许关闭。
- 关闭后把焦点返回触发元素或下一步逻辑位置。
- 提供可见关闭或取消控件；不要依赖点击遮罩作为唯一退出方式。
- 不在模态框中再打开模态框。

### 5.2 抽屉与侧面板

- 用于需要保留背景列表或对象上下文的详情、快速编辑和辅助信息。
- 固定标题和主要动作时保证正文拥有单一明确滚动容器。
- 对未保存修改提供离开保护；对象切换时处理脏状态。
- 内容需要深链接、复杂对比或多步骤流程时升级为完整页面或可调整分栏。

### 5.3 Popover、Tooltip 与菜单

- Tooltip 解释控件，不承载必须操作或必须阅读的信息。
- Popover 承载短小非阻塞交互，必须支持键盘打开、关闭和焦点管理。
- 菜单项使用动作名称，显示危险和禁用原因；不要把互斥选择伪装为动作菜单。

弹层和复合控件的键盘模型优先遵循 [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/patterns/)，不要只添加 ARIA 属性却缺少对应交互。

## 6. 键盘与专家路径

- 使用原生元素和组件库既有键盘模型，避免自创键位。
- 为跨页面搜索、命令、保存、提交、关闭和队列前后项提供一致快捷方式时，显示可发现提示。
- 焦点样式在科技蓝主题下保持清晰，不被 `outline: none`、裁切或固定层遮挡。
参考 [WAI-ARIA Dialog (Modal) Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 校验复杂交互。

## 7. 自动刷新与实时数据

- 显示最后更新时间、连接状态和刷新频率，允许暂停或手动刷新。
- 用户正在选择、编辑、展开或阅读时，不重排可见行；可先提示“有新数据”。
- 合并更新时保持对象身份稳定，不因数组位置变化丢失焦点或展开状态。
- 数据过期与连接中断使用状态文字和时间戳，不只改变圆点颜色。
- 对影响决策的实时页面提供历史、冻结时间或快照，以便复核和审计。

## 8. 性能与稳定性

- 优先测量用户任务而不是单一渲染指标：首次可操作、输入响应、筛选结果、详情切换和批量提交。
- 减少无效重渲染、重复请求、海量 Tooltip 和不可见 DOM；在优化大量数据视图前验证键盘、选择、滚动恢复和辅助技术。
- 加载占位与最终内容保持相近几何，避免累计布局偏移。
- 动效通常使用 150–250ms 的非阻塞过渡，并遵循 `prefers-reduced-motion`；高频操作不使用超过 300ms 的装饰转场。
- 性能失败时先保持操作正确和状态透明，再降级动画、预览或非关键可视化。

## 9. 验证矩阵

至少覆盖以下组合中与任务有关的部分：

| 维度 | 样例 |
| --- | --- |
| 数据 | 0 条、1 条、一页、跨页、大量、长标识、缺失值 |
| 权限 | 可编辑、只读、字段受限、动作受限、会话中权限变化 |
| 网络 | 快速、慢速、超时、离线、部分失败、重复提交 |
| 输入 | 鼠标、键盘、粗指针、输入法、复制粘贴 |
| 布局 | 默认密度、紧凑密度、窄窗口、缩放、长文案、多语言 |
| 状态 | 初次加载、刷新、空、无结果、错误、过期、部分成功 |
| 连续操作 | 快速切换对象、批量选择、返回、刷新、恢复草稿 |

验证时记录目标浏览器、视口、缩放、数据规模、权限和未覆盖边界。对状态消息参考 [WCAG 2.2 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。
