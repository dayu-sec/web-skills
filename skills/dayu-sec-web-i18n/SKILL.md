# DayuSec Web 国际化文案组织

## 工作顺序

1. 确认当前业务场景所属的领域，以及该领域是否已有命名空间；沿用既有命名空间优先于新建。
2. 读取 [命名空间与粒度](references/namespace-and-granularity.md)，判断文案落在领域命名空间还是公共命名空间，并据此组织键。
3. 新建命名空间时，在应用支持的每种语言目录下同时创建同名文件，并把它加入应用的命名空间声明清单。
4. 组件按命名空间消费文案：领域在前，需要公共文案时追加。
5. 交付时说明命名空间的领域归属，触及公共命名空间时单独说明。

## 边界

- 给出业务侧文案组织的倾向与理由，不替代目标项目的既有约定。项目已有不同组织方式时以项目为准，先建立映射再判断是否值得迁移。
- 语言运行时装配、语言偏好的解析与持久化、跨应用语言广播和语言切换副作用由语言域实现拥有，不在本 Skill 范围内。
- 命名空间是文案的所有权单位，也是并行开发的隔离单位。跨领域复用的成本由公共命名空间承担，不通过互相引用其它领域的键实现。
- 公共命名空间是应用内唯一的共享面，准入从严；默认答案是留在领域命名空间。
- 文案以完整句子为单位，不在运行时由片段拼接。语序随语言变化，拼接出的句子无法通过修改译文纠正。
- 命名空间的声明清单、各语言目录下的文件与键集三者不一致时不会导致构建失败，只在运行时显现，新增和搬迁时一并处理。

## 引用入口

- [命名空间与粒度](references/namespace-and-granularity.md)：领域划分与所有权、公共命名空间准入、文案粒度与消费形态。

## 输出要求

- 说明本次新增或修改的命名空间及其领域归属。
- 触及公共命名空间时单独标注，说明它被哪些领域共同使用。
- 列出同步创建的各语言文件。
