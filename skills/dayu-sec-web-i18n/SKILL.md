# DayuSec Web 国际化文案

## 工作顺序

1. 读取目标仓库的 `AGENTS.md`、语言目录、命名空间声明清单与既有键的组织方式，确认本仓库已经成立的约定；沿用既有命名空间优先于新建。
2. 把本次范围定在一个业务领域，而不是一个页面或一次提交。领域是并行开发的隔离单位，按领域推进才不会和别人改同一个文件。
3. 找出范围内尚未接入的中文，读取 [存量中文的识别与分界](references/copy-migration.md)：先把文案与数据分开，再决定哪些需要接入、哪些要保留并写明理由。
4. 组织键，读取 [命名空间与粒度](references/namespace-and-granularity.md)：判断文案落在领域命名空间还是公共命名空间，并据此命名。
5. 落地取值，读取 [取值时机与句子形态](references/runtime-resolution.md)：确认每处取值都发生在语言就绪之后，且句子不是运行时拼出来的。
6. 新建命名空间时，在应用支持的每种语言目录下同时创建同名文件，并加入命名空间声明清单。
7. 交付前当场核对：命名空间声明清单、各语言目录下的同名文件、各语言的键集、同一键在各语言里的插值变量集合，以及每份语言文件里没有混进别的语种。这一步是核对，不是补测试。
8. 运行目标仓库既有的类型检查、Lint、格式与构建命令；仓库有未提取文案的扫描或棘轮时一并运行，并只下调本次真正处理过的文件。

## 职责边界

- 本 Skill 指导"文案怎么组织、怎么接入、哪些不该接入"。语言运行时装配、语言偏好的解析与持久化、跨应用语言广播和语言切换副作用由语言域实现拥有，不在范围内。
- **不产出 i18n 测试。** 键集齐平、插值变量一致、英文资源里没混中文，这类断言比对的是资源文件与它自己的另一份拷贝，不执行任何被测逻辑：文案改一次要改两处，而缺键、命名空间写错、取值时机不对时它照样是绿的。它们是 `$dayu-sec-web-testing` 里的变更探测器与接线断言，交付前对着文件核对一遍即可。目标项目已有这类用例时，按该 Skill 的清退手法处理，不要新增。
- 同理不为"某组件调用了 `t()`"、"某个 Provider 已注册"这类接线写用例。它们证明代码写了这一行，不证明界面上能看到正确的文案。
- 命名空间是文案的所有权单位，也是并行开发的隔离单位。跨领域复用的成本由公共命名空间承担，不通过互相引用其它领域的键实现。
- 公共命名空间是应用内唯一的共享面，准入从严；默认答案是留在领域命名空间。
- 目标项目已有不同的组织方式时以项目为准，先建立映射，再判断是否值得迁移。

## 引用入口

- [存量中文的识别与分界](references/copy-migration.md)：怎么把遗漏的中文找全、文案与数据的分界、错误与日志文本按调用链的取舍、失效中文默认值的清退。
- [命名空间与粒度](references/namespace-and-granularity.md)：领域划分与所有权、公共命名空间准入、文案粒度与消费形态。
- [取值时机与句子形态](references/runtime-resolution.md)：模块顶层与参数默认值的求值时机、非 React 模块的取值出口、句子完整性与内嵌标记、语言切换的副作用。

## 输出要求

- 说明本次新增或修改的命名空间及其领域归属；触及公共命名空间时单独标注，说明它被哪些领域共同使用。
- 列出同步创建或修改的各语言文件，并给出各语言键数是否齐平的核对结果。
- 列出判定为"数据不是文案"而保留的中文及其理由。同一条理由要写进源码注释：下一个人的第一反应仍然是把它翻译掉。
- 列出清退的失效中文默认值；其中默认值与译文已经漂移的单独点名——那是源码在误导读者，删掉才消除误导。
- 错误与日志文本给出按调用链的结论：哪几处会冒泡到用户因而接入，其余为什么不接入。
- 报告运行过的命令与结果；涉及未提取文案的扫描时，说明基线的变化范围与未处理文件是否发生漂移。
