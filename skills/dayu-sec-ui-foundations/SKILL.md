# DayuSec UI 工程基础

## 工作顺序

1. 读取目标仓库 `AGENTS.md`、已经确认的产品 UI/UX 规范、主题配置和组件入口，确认产品类型、真实业务边界与当前技术栈。
2. 先选择对应产品 UI/UX 依据：内部运营、工作台和管理后台使用 `$dayu-sec-ui-internal-ops`；其他产品只使用目标仓库已确认的规范和实现，不从本 Skill 推断视觉方向。
3. 阅读 [跨产品 UI 工程基础](references/ui-engineering-foundations.md)，建立产品规范、语义 Token、组件库和页面实现之间的映射。
4. 先复用目标项目的 Token 和基础组件，再新增缺失的工程角色；避免页面级字面量、无边界全局覆盖和重复主题来源。
5. 目标项目采用 shadcn/ui 与 Tailwind CSS 时同时使用 `$dayu-sec-ui-shadcn`；采用其他组件库时遵循其项目约定或对应技术 Skill。
6. 验证键盘操作、焦点可见性、折叠与展开、窄屏、滚动归属、浅深主题及加载、空、错误和权限状态。

## 工程原则

- 以对应产品 UI/UX Skill、目标项目已确认的规范、导航、权限、路由和业务文案为准；设计原型只提供证据，不自动成为跨产品规范。
- 产品 Skill 拥有配色、间距、字阶、控件尺寸、密度和页面模式；本 Skill 只负责把这些决策稳定映射到工程实现。
- 使用语义角色承接产品规范，不在组件中复制主题字面量，也不在这里为语义角色规定具体取值。
- 保留原生语义元素、ARIA 状态和可预测的 Tab 顺序；图标按钮必须有可访问名称。
- 主题、响应式与状态实现必须保持单一所有者，避免 Shell、页面和组件分别维护不一致的 Token 或文档级副作用。
- 本 Skill 不选择 CSS 工具、组件原语、表单状态库或源码生成方式。

## 输出要求

- 说明采用的产品 UI/UX 依据、工程边界，以及新增或复用的语义 Token 映射。
- 列出主题作用域、布局、滚动、状态、响应式和可访问性变化；具体视觉数值与页面模式由对应产品 Skill 报告。
- 报告已运行的静态、单元、构建和浏览器验证；未完成的主题、响应式或视觉检查必须明确标注。
