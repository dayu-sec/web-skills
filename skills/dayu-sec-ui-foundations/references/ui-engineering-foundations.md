# 跨产品 UI 工程基础

## 1. 所有权

- 对应产品 UI/UX Skill 或目标项目已确认规范拥有品牌配色、间距、字阶、控件尺寸、密度、圆角、材质和页面模式。
- 本文件只定义这些产品决策进入 Token、主题、组件和页面实现时的跨产品工程边界，不提供默认视觉方向或数值。
- 设计原型、其他产品实现和组件库默认主题都只能作为证据，不能自动升级为团队通用设计语言。
- 内部运营和管理后台的产品规则使用 `$dayu-sec-ui-product-internal-ops`；面向客户和终端用户的客户端产品使用 `$dayu-sec-ui-product-client-facing`；其他产品以目标仓库已确认规范为准。

## 2. 语义 Token 与主题

- 先识别表面、文字、交互、结构、焦点和状态等语义角色，再把产品规范映射到目标项目的 Token 命名。
- 浅色、深色、高对比度或品牌变体维护同一组语义角色，不让组件通过字面颜色判断主题。
- 品牌主色与成功、警告、危险、中性状态分离；具体色值和使用强度由对应产品规范决定。
- 组件使用语义 Token，不复制产品色值、字号、间距、圆角或阴影字面量；必要例外沉淀到组件级 Token。
- 文档根、应用根和子应用主题作用域必须有明确所有者，避免多处同时写入主题类或 CSS 变量。

## 3. 布局与滚动

- 应用根负责视口与大区编排，内容区负责主要滚动；不要让文档、Shell 和页面形成竞争滚动容器。
- Flex 或 Grid 子项需要收缩时显式处理最小尺寸约束，避免长文本、图表或业务内容撑破容器。
- 固定页头、侧栏、工具区和浮层必须保留内容可见区域、焦点路径和到达最后一项的滚动能力。
- 响应式行为由产品任务和目标设备决定，明确导航、工具区、内容和浮层在窄窗口下的重排、折叠或替代方式。

## 4. 组件与状态

- 复用组件库公开的主题与变体接口，不覆盖其未承诺稳定的内部结构。
- Hover、Focus、Active、Selected、Disabled、Read-only、Loading、Empty、Error 和 Permission-denied 状态保持语义清晰，切换时避免布局位移。
- 加载、空、错误和权限状态保留页面或对象上下文，并提供符合权限与风险的下一步。
- Portal、通知和浮层必须位于正确主题作用域，关闭或卸载时释放焦点、滚动锁和文档级副作用。

## 5. 可访问性与输入方式

- 优先使用原生语义元素；用 ARIA 补充组件状态和关系，不用 ARIA 替代可用的原生行为。
- 保持可预测的键盘顺序、可见焦点、可访问名称和打开后关闭前后的焦点回收。
- 颜色不是状态的唯一表达；文字、图标、位置或形状按风险与扫描需求提供冗余线索。
- 目标尺寸、文字对比度、缩放和减弱动效遵循目标项目采用的可访问性基线，不从本文件推导产品视觉尺寸。

## 6. 验证

- 静态检查 Token 来源、主题所有权、全局选择器、任意视觉字面量、语义元素和 ARIA 状态。
- 在真实浏览器验证主题切换、键盘、焦点、缩放、窄窗口、长内容、滚动、浮层和主要异常状态。
- 微前端同时验证独立运行、宿主集成、重复挂载和卸载，确认主题、Portal 与文档副作用不泄漏。
- 无法使用目标浏览器时，只报告静态、测试和构建证据，不宣称视觉或几何验收完成。
