# 请求运行时与实例归属

## 配置与初始化

- 先定位项目已有的请求配置、应用入口、语言服务、认证状态和生命周期，不为接入请求包复制第二套基础设施。
- 每个请求实例使用稳定且能表达所有者的名称；同一运行时内不得让多个模块隐式接管同名实例。
- 在任何业务 Service 发起请求前完成初始化。初始化函数应允许入口重复调用而不重复注册实例、拦截器或全局副作用。
- 请求地址、超时、请求头和拦截器沿用目标仓库契约；迁移请求包不顺带改变业务路径、代理或响应拆包方式。

## 会话与请求头

- Token 存储键、Token 是否包含认证方案前缀、语言值来源和自定义请求头都必须来自项目契约或已验证实现。
- 不猜测存储键、认证格式、租户头或语言格式，也不在代码和 Skill 示例中写入真实凭据。
- 请求头注入由实例拥有的拦截器完成，保留消费方原有拦截器顺序和错误传播语义。
- 多个应用共享同一页面运行时时，明确会话状态属于宿主、子应用还是独立请求实例，不使用可变全局对象隐式共享。

## 生命周期与清理

- 无卸载生命周期的单体应用只需在启动阶段初始化，不为形式一致增加无调用方的清理入口。
- 有应用生命周期时提供明确的 `setup` 和 `cleanup`，具体挂载、卸载与重复装配验证由 `$dayu-sec-web-micro-frontend` 约束。
- 清理只释放当前请求层拥有的实例、拦截器、会话状态和错误策略，不删除其他调用方创建的实例或全局策略。
- 清理后再次初始化必须能够复用原实例名，并重新读取当前语言和认证状态。

## 失败边界

初始化参数无效、实例名冲突或底层注册失败时立即暴露错误并回滚当前尝试，不留下半初始化状态，也不用多路径兜底掩盖所有权冲突。
