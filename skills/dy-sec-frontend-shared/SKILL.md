# DySec 前端通用工程

## 工作顺序

1. 读取目标仓库的 `AGENTS.md`、前端框架、路由方案、目录约定、构建配置和相关基础设施，确认机制的实际入口。
2. 涉及文件路由、页面目录或业务视图目录时，读取 [文件路由与业务视图边界](references/file-routing-and-views.md)。
3. 涉及前端数据请求、实例生命周期、Token 请求头或请求错误传播时，同时使用 `$dy-sec-frontend-request`；本 Skill 不复制请求规则。
4. 只在本 Skill 定义框架无关协议；React、Vue 或其他框架的 Router API、组件通信和生命周期由相应框架 Skill 适配。
5. 任务涉及宿主、子应用、装配、隔离或跨应用契约时，同时使用 `$dy-sec-microfrontend`；单体 Web 不加载微前端规则。
6. 修改后运行目标仓库已有的类型、Lint、格式、测试和构建命令；路由变更同时验证直接 URL、刷新和历史导航。

## 引用入口

- [文件路由与业务视图边界](references/file-routing-and-views.md)：设计、迁移或评审文件路由入口与业务视图的团队统一分层协议时读取。

## 输出要求

- 说明框架无关机制与框架适配各自的职责，不把 React 或 Vue 写法提升为通用协议。
- 指出保留的项目约定、迁移范围、必要例外和验证证据。
- 发现路由入口承载业务逻辑、扫描排除规则掩盖目录失范或业务视图依赖文件命名时，明确报告或修复。
