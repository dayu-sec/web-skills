# Tailwind、主题与隔离

## Tailwind v4 与主题

- Vite 项目优先使用 `@tailwindcss/vite`，入口 CSS 导入 `tailwindcss`；保留目标仓库其他构建插件的既有职责。
- 在 `@theme inline` 中将 Tailwind 颜色、圆角和字体映射到 CSS 变量；`:root` 与深色主题选择器只维护 Token 值。
- 产品 UI/UX Skill（如 `$dayu-sec-ui-product-internal`）给出的字号、行高和间距语义刻度，同样要落地为 `@theme` 里的 `--text-*`、`--spacing-*` 覆盖，而不是只写进文档。Tailwind 默认字号刻度（12/14/16/18/20/24px）与业务常见语义刻度（如 12/13/14/16px）不一定对齐；覆盖 `--text-xs`/`--text-sm`/`--text-base` 等变量或新增 `--text-meta`/`--text-body` 之类语义变量，使 `text-*` 类直接产出目标像素值，不要求业务代码记住某个语义对应哪个任意像素。
- 业务代码里出现 `text-[Npx]`、`p-[Npx]`、`gap-[Npx]` 等任意值语法，是主题层字号/间距 Token 缺口的信号，不是"这一处刚好需要精确到像素"的正常用法；发现后优先回到 `@theme` 补齐对应 Token，而不是让任意值在页面间反复出现。
- 组件使用语义类，不复制品牌色字面量。动态生成的类不能被扫描器静态发现时，改用完整类映射或显式来源声明。
- 主题切换要同步可访问的文档或应用根状态，并在首屏渲染前避免错误主题闪烁；具体品牌值使用目标项目已确认的规范或对应产品 UI/UX Skill。

## 单体与宿主

- 单体应用或平台宿主可以在文档级加载 Preflight、根字体和画布样式，但仍要为应用内容建立明确滚动容器。
- 全局重置、CSS 变量和深色选择器必须有单一所有者；不要让页面或业务组件重复写入 `html`、`body`。

## 微前端

- 子应用不拥有宿主文档，不直接覆盖 `html`、`body`、宿主根或其他子应用节点；Preflight 是否加载由宿主契约决定。
- 子应用的 CSS 变量、主题类和布局样式限定在自身根节点。需要独立运行时，由独立入口提供等价根作用域，不把宿主兼容分支散落到组件中。
- Dialog、Menu、Select、Popover、Tooltip 等 Portal 明确挂载容器和主题作用域；z-index、滚动锁和焦点不得污染相邻应用。
- 卸载时清理应用创建的样式节点、Portal、监听、订阅和文档状态；重复挂载不能累积副作用。

## 验证矩阵

- 单体或宿主：直达、刷新、历史导航、深浅主题、窄屏、长内容和主要滚动区。
- 子应用：独立运行、宿主首次与重复挂载、卸载重挂、主题同步、多个应用切换或并存。
- 所有形态：键盘焦点、浮层定位和裁切、字体与图标资源、非根路径制品、最终 CSS 扫描和生产 chunk。
