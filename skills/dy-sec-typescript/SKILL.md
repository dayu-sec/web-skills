# DySec TypeScript

## 工作方式

1. 读取目标仓库的 `AGENTS.md`、相关源码、类型和契约，沿用现有命名、模块和质量门禁约定。
2. 处理类型建模、空值、外部输入、类型收窄、泛型、断言或异步错误时，读取 [严格模式与类型安全](references/strictness-and-type-safety.md)。
3. 处理模块格式、类型导入、声明文件、包导出或项目引用时，读取 [模块、声明与包边界](references/modules-declarations-and-packages.md)。
4. 处理代码规范、反模式、类型感知 Lint、格式职责或质量门禁时，读取 [代码质量与工具边界](references/code-quality-and-tool-boundaries.md)。
5. 处理 TypeScript 版本、`enum` 替代、可擦除语法、官方废弃能力或升级兼容时，读取 [语言演进与废弃能力](references/language-evolution-and-deprecations.md)。
6. 仅在任务直接修改 TypeScript 配置、声明构建、模块解析、类型感知 Lint，或现有门禁指向配置问题时，检查相关 TypeScript 版本、`package.json`、`tsconfig` 和工具配置；普通源码任务不主动审计或迁移脚手架配置。
7. 修改公共契约、数据解析或错误结构时，同时使用 `$dy-sec-data-contract-first`；修改 React 组件职责时同时使用 `$dy-sec-react`。本 Skill 不复制框架、架构或业务规则。
8. 修改后优先运行仓库已有的统一质量门禁；没有统一入口时再运行与变更相关的检查。只有触及构建、声明、导出或发布边界时，才追加构建、打包和真实消费者验证。

## 规则优先级

1. 用户当前要求和目标仓库 `AGENTS.md`。
2. 现有公共契约、数据契约和真实运行时。
3. TypeScript 类型安全与可维护性。
4. 项目已有代码规范和质量规则。
5. 格式化工具生成的纯格式结果。

不通过 `any`、双重断言、非空断言、降低严格度或批量禁用规则绕过问题。除非用户明确要求或配置已被确认是根因，否则不修改脚手架配置；必要例外限制在最小边界并说明原因。

## 输出要求

- 说明与本次任务直接相关的类型、契约或运行时影响，以及实际完成的验证。
- 只有任务涉及配置、模块或工具链时，才说明对应版本、模式和质量命令。
- 新增不可避免的断言、`any`、环境声明、规则禁用或兼容分支时，说明来源、作用域和退出条件。
- 评审时优先报告掩盖运行时不确定性、破坏公共类型、遗漏异步错误或错误描述模块边界的问题。
